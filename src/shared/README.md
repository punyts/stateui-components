# shared

CSS partials and base controllers used by more than one component. They live here, outside `components/`, because the
build's convention scan rejects any file in `components/` that is not part of a component folder.

## css/
Partials a component's `view.css` pulls in with a line `@include "<name>.css";` (the build's `sharedCssDir`, set in `scripts/buildComponents.mjs`). The token lint checks them inside each component that includes them.
- `control.css`: the class `.control` for a bare native control (border, radius, padding, minimum height from `--control-height`, placeholder, read-only, disabled and focus states) from the `control` tokens. Used by `input` and `textarea`.
- `overlay.css`: the dialog, backdrop, frame, header, close button, body and footer of `modal` and `drawer`; the including view sets `--pad`, `--gap` and `--radius` on `.dialog`.

## shape/
Shape partials a component's `state.json` merges in with `"includes": ["<name>"]` (the build's `sharedShapeDir`, set in `scripts/buildComponents.mjs`): `<name>.json` holds only `properties`, `events` and `tokens`, merged under the component's own (an own property or token wins), so the catalog shows the merged shape. `paint.json` (`fill`, `stroke`, `strokeWidth`, `opacity`, `dash`, `cap`, `join`), `transform.json` (`x`, `y`, `rotate`, `scale`, `origin`), `interaction.json` (`interactive`, `_label`, `draggable`, `bounds`, `step`; events `press`, `hover`, `dragEnd`) and `motion.json` (`transition`, `animate`), merged by the 2D shapes of `drawing`. The 3D nodes of `scene3d` merge `transform3d.json` (`position`, `rotation`, `scale` as three numbers, `visible`), `interaction3d.json` (`interactive`, `_label`; events `press`, `hover`) and `motion3d.json` (`transition`, and `animate` with the 3D names `spin`, `bob`, `pulse`).

## scene3d/
`load.ts`: `LOAD_3D_EVENT` (`ui-load-3d`), `requestScene3dChunk(target)` (raises the bubbling, composed event in the request shape of `ui-file-read`, `detail.respond(promise)`; rejects `{ code: 'offline' }` when nothing answers, `failed` when the hook rejects, `invalid` when it gives no chunk), `isScene3dChunk` and the types `Scene3dChunk` and `Load3dRequest`. `scene3d` imports it as `../shared/scene3d/load.js`.

## field/
`field.ts`: `createField(context, valueName, options)` (options `entryRule`, `exclusive`, `empty`, `onReset`), the base controller of every field (glyph, message, baseline, `validate` and `reset` commands, `change`, `invalid` and `valid` events, `focus` and `clear` commands, the `ui-field-connect` event with `FieldConnect`, `touched` and `dirty`; the options `entryRule`, `exclusive` and `empty` for a field with a value of its own kind, such as `dateRangeField`) and the layout helpers; `rules.ts`: `failingRule`, `patternOf`, `NAMED_PATTERNS` and `FIELD_RULES`, the pure validation rules.
`files.ts`: the pure parts of `fileField`: `ALLOWED_FILE_TYPES` (the ADR-0017 list and `model/gltf-binary`, G3.7; pinned to the same literal as the server's `UiFile.ts` in both libraries' tests), `MAX_FILE_SIZE` (10 MiB), `effectiveAccept` (`accept` narrowed to the list), `effectiveMaxSize`, `effectiveMaxFiles`, `mediaTypeOf` and `typeFromName` (the type of a file the browser gave none), `acceptAttribute`, `isFileRef`, `formatBytes`, `percentOf` and `transferCode`. Stored files (G2.9b, shared since G1.9b): `FILE_READ_EVENT` (`ui-file-read`), `IMAGE_FILE_TYPES` (png, jpeg, gif, webp), `StoredFile` and `ReadStoredFile`, `readStoredFile(target, id, signal)` (raises the bubbling, composed event; rejects `{ code: 'offline' }` when nothing answers) and `readImageBitmap(read, id, signal)` (the bytes decoded with `createImageBitmap` on a `Blob`; rejects `{ reason }`, the read's code or `not_an_image`); `paintField` backgrounds and `drawImage` use them.


## format/
`format.ts`: `formatValue(value, { format, locale, currency, signed })` formats a number with `Intl` for a language (`number`; `percent` from 0 to 1, up to one decimal; `currency` with an ISO 4217 code; `duration` from seconds as `m:ss`, or `h:mm:ss` from one hour) and returns an empty string for a value that is not a number. An unusable locale falls back to `en`, a currency code `Intl` refuses to a plain number. `stat` uses it; the `table` and `descriptionList` columns will. Controllers import it as `../shared/format/format.js`.

## slider/
`slider.ts`: the pure parts of `sliderField`: `readScale` (min, max and step from the node), `snapValue`, `readThumbs`, `percentOf`, `limitsOf` (a range's thumbs hold each other), `valueForKey`, `valueAtFraction` and `nearestThumb`. `sliderField` imports it as `../shared/slider/slider.js`.

## steps/
`steps.ts`: the pure parts of `stepper`: `planSteps` (number, done, current and disabled for every step, with the `linear` rule), `currentStep` and `keysOf`. `stepper` imports it as `../shared/steps/steps.js`.

## split/
`split.ts`: the pure parts of `splitPane`: `readBounds` (`min` and `max`, each inside 0 to 100, `max` never below `min`), `clampSplit`, `splitForKey` (5% per arrow key, Home and End, Left and Right swapped in right-to-left text), `splitForDrag` (pixels to percent of the container, clamped), `KEY_STEP` and `DEFAULT_SPLIT`. `splitPane` imports it as `../shared/split/split.js`.

## tone/
`toneGlyph.ts`: `toneIcon(tone)` gives the default icon of a tone (`info-circle` for `info`, `neutral` and `accent`, `alert-circle`, `alert-triangle` and `circle-check` for `danger`, `warning` and `success`). `toast` uses it; a controller imports it as `../shared/tone/toneGlyph.js`.

## popover/
`popover.ts`: `createPopover` (popover API, CSS anchor positioning from a `placement` or an `anchor` name, Escape and outside-press dismissal, no layout reads; no component needed, exported from the package), `positionAreaOf`, `isPlacement`, `isAlignedPlacement`, `isAnchorName`, `PLACEMENTS` and `ALIGNED_PLACEMENTS`. `tip.ts`: `attachTip` (show after a hover delay, at once on focus, hide on leave and blur). `tipMixin.ts`: the `tip` and `tip-describes` attribute directives and `registerTipMixins()`; `tooltip` and the icon-only `button` import it as `../shared/popover/tipMixin.js` and put `tip="" tip-describes="_text"` on their popover element, the element after the trigger.

## overlay/
`overlay.ts`: `registerOverlayMixin()` registers the `overlay` attribute directive, put on the `<dialog>` of a view: it keeps the dialog open as the component's `open` property says (`showModal()`, `close()`, focus returned to the opener), closes it on Escape and a backdrop press while `dismissible` is not false by writing `open`, and raises `open` or `close` on the host once per change of `open`. `createOverlayController(context)` gives the commands `open`, `close` and `toggle` and the handler `onClose`, which only write `open`. `deepActiveElement` is the focused element through open shadow roots. `modal` and `drawer` import it as `../shared/overlay/overlay.js` and pull the layout parts in with `@include "overlay.css";`.

## records/
`window.ts`: `readWindow`, `poolSize(count, overscan)` (visible rows plus the overscan on both sides, at most `MAX_SLOTS` = 200, taken from the overscan first) and `poolStart`. `recordIndex.ts`: `createRecordIndex`, the key-to-position bookkeeping of an array (a key-to-index map kept from the store events) or a keyed map, with `order`, `keyAt`, `pathOf`, `locate` (the record path, or `$.runtime.empty`) and `size`. `slotPool.ts`: `createSlotPool`, the slot nodes in the runtime branch recycled by re-pointing one `row` link. `recordList` and `recordGrid` use them as `../shared/records/*.js`.

`gridViewport.ts`: the pure parts of `recordGrid` and its observer. `columnsFor(width, itemMin)` (`floor(width / itemMin)`, at least 1), `rowsFor(total, columns)`, `gridWindow(scrollTop, viewport, rowHeight, columns)` (whole rows reaching into the viewport as `{ first, count }` in row-major item positions) and `bandOffset` (the scroll offset that brings a band into view). `createGridViewport({ scroller, probe, onChange })` is the grid's counterpart of `createViewportObserver` and the one place the grid reads layout: a scroll listener reads `scrollTop` once per frame, and a `ResizeObserver` reports the scroller's content size and the probe's size (`itemmin` wide, `itemheight` high) from its entries. `scrollTo(offset)` is a write.

`rowLayout.ts`: `createRowLayout(source)`, the vertical layout of a `recordGrid` whose items differ in height: a height map keyed by record (`measure`), the estimate for the records not measured (`configure(columns, estimate)`), the row heights (the tallest item of a row), their tops, the total (`height`), `rowAt(offset)` by binary search and `offsetOf(position)`; `invalidate` after the keys moved. `layoutWindow(layout, scrollTop, viewport, columns)` is the window of whole rows. `slotMeasure.ts`: `createSlotMeasure({ onMeasure })`, one `ResizeObserver` over the slot elements that reports each slot's index and border-box height from the entries; `refresh(element)` observes an element again, which reports it at once. `slotPool.ts` also takes the option `offset(position)`, which a slot shows as `slotOffset`, and has `syncOffsets()`.

`tree.ts`: the pure parts of `tree`: `buildTree` (records to a `TreeModel`: nodes, roots in display order and the keys a cycle hides), `flattenModel` (the visible `TreeRow`s for a set of expanded keys, iterative) and `flattenTree` (both). `recordView.ts`: the element hooks of a record view, including `slotMeta` (what a wrapping component tells the pool about each record in a slot) and `invalidate`.

`placeholder.ts`: `placeholderKey(owner)`, `isPlaceholderKey` and `placeholderOwner`: a key in `order` that names no record, for a row a view shows while it waits for records (`tree`: the busy row under a record whose children are loading). The record index accepts such keys in `order`, the pool shows their positions as pending slots, and `recordKeys()` leaves them out.

## selection/
`selection.ts`: `createSelection({ store, selectedPath, currentPath, mode, locate, onSelect })` keeps a record view's selection in `selected` (`pick` replaces or toggles by mode, `selectAll` in `multi` mode only, `clear`) and the store link `current`, pointed at the selected record from `locate` in `single` mode, otherwise at the protected `$.runtime.empty`; `relocate` re-points it after the records changed. Pure helpers: `readSelectionMode`, `selectionKeys`, `selectionValue`, `pickKey`, `sameKeys`, `SELECTION_MODES`. `list` uses it as `../shared/selection/selection.js`; `table` uses it too.

## order/
`sortOrder.ts`: `createSortOrder({ store, recordsPath, orderPath, key, sortBy, direction, schedule })` writes the sorted key array `order` (with `replace`, one event) from the records path and one `<records>.$every.<sortBy>` wildcard, once per `schedule` call; `refresh` after the sort field or direction changed. Pure helpers: `sortedKeys` (stable; empty values last in both directions), `compareSortValues`, `readSortEntries`, `fieldValue`, `readSortDirection`. `list` uses it as `../shared/order/sortOrder.js`; `table` uses it too.

## chart/
`scale.ts`: the pure parts of every chart type: `createLinearScale`, `createBandScale` (both with `invert`), `niceTicks` (round tick values, labels from a formatter the caller gives), `stack` (positive values up and negative values down from 0), `extentOf` and `stackExtent`. No DOM and no locale code. `chart` imports it as `../shared/chart/scale.js`.

`geometry.ts`: `buildScene(input)`, the pure drawing of a bar, line or area chart as a flat list of SVG primitives (`id`, `layer`, `tag`, `className`, `attrs`, `text`) with stable ids, plus `seriesClass` (`s1` to `s8`, the categorical data colours in series order) and `SERIES_COLORS`. The margins are estimated from the label text, so nothing reads layout. `drawingTree.ts`: `sceneToTree(scene)` turns a scene into the shape tree the drawing renderers draw (G2.1); the chart draws it with the SVG renderer of `drawing/` (G2.2), which replaced `svgScene.ts`. `data.ts`: `readRows` (an array or a keyed map of records), `readSeries`, `readCategories` and `readValues`.

`scene.ts`: the types of a drawing (`ChartInput`, `Primitive`, `Point`, `Scene`, `TipRow`, `ChartTexts`), `CHART_TYPES`, `seriesClass`, and the helpers `px`, `attrs`, `emptyScene` and `markAttrs` (the name, role and `data-point` of a mark). `geometry.ts` now holds `buildCartesian` (bar, line, area); `donut.ts`: `buildDonut`; `chart.ts`: `buildScene`, which picks between them. `table.ts`: `tableModel` (the values as headers and rows, hidden series included) and `createDataTable`, which draws a `table` with `createElement` and writes only the cells that changed. `navigate.ts`: `pointAfter` (arrow keys, Home and End between points, all four arrows round a ring) and `tabStop`.

`board.ts`: `buildBoard(records, { key, columnField, orderField, columns })`, the pure sorting of records into the columns of a `board`: the record keys of each column in display order (sorted by `orderField`, numbers ascending, records with no number after them, ties in record order) and the distinct column values that no column has. `columnValue` is the text a value is matched by. `board` imports it as `../shared/records/board.js`.

## drag/
`drag.ts`: the pure parts of moving a card by pointer and keyboard (`board`): `passedThreshold` (4 pixels turn a press into a drag), `columnAt` (the column under the pointer by its horizontal position, or the nearest), `dropIndex` (the index of the card the pointer is over from the pointer height, the column top and scroll and the card height; one past the last card for another column), `placeAfterKey` (Up and Down inside a column, Left and Right between columns, swapped in right-to-left text, with and without an order field) and `announce` (fills `{name}` style fields of an announcement template). `board.ts` also has `planMove`, the writes of a move: the column, and an order number between the new neighbours or the whole column numbered from 1. `board` imports them as `../shared/drag/drag.js` and `../shared/records/board.js`.

## dates/
`isoDate.ts`: calendar arithmetic on ISO dates with no `Date` object (`dayNumber`, `fromDayNumber`, `addDays`, `addMonths`, `monthGrid` (6 × 7 days), `startOfWeekDay`, `weekdayOfDay`, `todayIso`), `parseIsoDate` and `parseMoment` (a date, or a date and time, as a day and a minute of the day). `weekStart.ts`: `firstDayOf(locale)` from `Intl.Locale.prototype.getWeekInfo()`, with the CLDR table `FIRST_DAY_BY_REGION` as the fallback. `localeDates.ts`: weekday and month names, month and long date titles, ranges, times, `formatDate` and `parseDate` for `$.locale`, from `Intl` (Gregorian calendar, UTC). `events.ts`: `readEvents` turns records (`startField`, `endField`, `titleField`) into `CalendarEvent` spans, `eventsOnDay` lists a day, `segmentOn` clips a timed record to a day and `layoutOverlaps` puts overlapping records side by side. `calendar` and `dateRangeField` import them as `../shared/dates/<file>.js`.

`calendarModel.ts`: the pure parts of `calendar`: `buildMonth` (the 6 × 7 grid of a focused date with each day's records, at most `MAX_PER_DAY` and a count of the rest, the heading, the weekday heads and the visible range), `buildTimeView` (the day columns of the week and day views: all-day records, and timed records clipped to the day with `start` and `span` in minutes and their overlap column), `visibleRange`, `stepDate` (previous and next: a month, a week or a day), `dateForKey` (the date a navigation key moves to in a view; Left and Right swap in right-to-left text) and `CALENDAR_VIEWS`. `calendar` imports it as `../shared/dates/calendarModel.js`.

`range.ts`: the pure parts of `dateRangeField`: `readRange`, `orderRange`, `rangeDays` (both ends counted), `failingRangeRule` (`required`, `order`, `min`, `max`, `minDays`, `maxDays`), `isPickable`, `pickDay` (the first press waits, the second finishes, reversed presses swap) and `markDay` (a day's place in the range). `picker.ts`: `buildPicker` (two months of 6 × 7 days, days of other months blank, each day marked with its range edge, today, the cursor and whether it can be picked) and `monthsFor` (which months to show so the cursor is on screen). `dateRangeField` imports them as `../shared/dates/range.js` and `../shared/dates/picker.js`.

## markdown/
`blocks.ts`: `parseBlocks(source)`, the block parser of the `markdown` component, a pure function to a tree of `{ type, children, text, level }` (`paragraph`, `heading`, `bulletList`, `orderedList`, `listItem`, `blockquote`, `code`, `rule`, `text`). Paragraphs and headings keep their inline source in `text`; a raw HTML block is a `text` block, shown as its characters. One pass over the lines with a stack of open containers and no regular expression on the text, so the time is linear; containers nest at most `MAX_BLOCK_DEPTH` deep and markers past that are text.
`inlines.ts`: `parseInline(text)` gives the inline nodes (`text`, `emphasis`, `strong`, `inlineCode`, `link`): the CommonMark delimiter algorithm (flanking and "multiple of 3" rules, a lower bound per kind of closer so the opener search is amortised), code spans closed through a table of the backtick runs, an image as its alt text, raw inline HTML as text, autolinks. A link target and title are looked for in a window of `TARGET_WINDOW` (1,024) characters; emphasis nests at most `MAX_INLINE_DEPTH` deep. `links.ts`: `safeHref(target)` resolves entities and escapes and keeps only `#`, relative in-app targets and `https://` (anything with a control character, whitespace, another scheme or `//host` gives undefined); `decodeTarget`. `tables.ts`: `tableFrom(paragraphText)` reads a GFM table that starts a paragraph (header row, delimiter row with `:--`, `:-:`, `--:`, body rows; rows are not padded) and `splitRow`. `nodes.ts`: `MarkdownNode` (`type`, `children`, `text`, `href`, `level`, `align`, every field always present). `markdown.ts`: `parseMarkdown(source, { profile, maxLength })` returns `{ children, truncated }`: the `basic` profile is blocks, inlines and tables, `inline` reads the whole source as inline content, and a source over `maxLength` (default 20,000) is cut at the end of the last block that fits whole (before a blank line, not inside a fence), else the last whole line, else the limit (`cutPoint`). All exported from the package. `render.ts`: `renderMarkdown(root, nodes, { headingOffset }, inline)` builds the DOM with `createElement` and `textContent` only (`headingTag` shifts and caps a level); a link is a `span` with `role="link"` and `data-href`, never an anchor. The `markdown` atom imports it as `../shared/markdown/render.js`.

## drawing/
The shared drawing model of `drawing` (and, in epic 2, `chart`): no DOM, tested in Node. `tree.ts`: `readShapeTree(children, path, { read })` reads a drawing's `children` map into the plain shape tree (`ShapeTree`: `kind`, `key`, state `path`, resolved `properties`, `children` of a `drawGroup` (of a `drawRepeat`, its bound copies once `expandRepeats` has run; `readShapeTree` leaves them empty), `row` of a `drawRepeat`, `clip` of a `drawGroup`, and an optional `attrs`) and lists the nodes whose component is not a 2D shape in `unknown` (left out with their subtree; the caller reports them). `read` reads a property through the store, so links are followed. `attrs` is only for feeders (a node cannot set it); `shapeAttrs` keeps `class`, `role`, `tabindex`, `aria-*` and `data-*`. `SHAPE_KINDS`, `isShapeKind` and `locateShape` (a shape by path, with its ancestors). A link the mount applied is a store alias the node object no longer shows (neither `<-key` nor `key`), so the option `properties(kind)` (pass `shapeProperties`; `SHAPE_PROPERTIES` lists each kind's declared properties, node slots left out, and `test/graphics.test.ts` compares it with the catalog) reads each declared property the node lacks through `read`.
`geometry.ts`: `readViewBox`, `readFit`, `fitViewBox` (a `viewBox` and `fit` to a scale and offset, centred as SVG's `xMidYMid`), `preserveAspectRatioOf`, `toDrawing`; matrices (`multiply`, `invert`, `applyMatrix`); `transformOf(shape)`: `scale` (a number or `[sx, sy]`) and `rotate` (degrees, clockwise on screen) about `origin` (`[x, y]`, default the centre of the shape's own bounds), then the `x` and `y` offset, which `rect`, `drawText` and `drawImage` take as their position instead; `localBounds`, `shapeBounds`, `treeBounds` and `boundsAt(tree, path)` (text bounds are estimated from its length and `size`); `hitLocal` and `hitTest(tree, x, y, { interactive })`: the topmost shape at a point, inside a closed shape or within half its `strokeWidth` (default 1) of the outline, `line` and `polyline` on the stroke only, `path` through `flattenPath`, groups through their transform and `clip`; with `interactive` the nearest interactive shape up from the topmost one, as an SVG pointer event finds it.
`render.ts`: the renderer contract. `createDrawingRenderer(target, options)` makes the renderer registered for `options.renderer` (`registerDrawingRenderer(kind, factory)`; `svgRenderer.ts` and `canvasRenderer.ts` register theirs when imported) and returns `{ update(tree), hit(x, y), boundsOf(path), elementOf(id), dispose() }`; the options carry `renderer`, `viewBox` (when the caller owns the sizing), `reducedMotion()`, `readProperty(name)` and `onEvent(ShapeEvent)`, and optionally `path` (the feeding node's state path, for the paths of `paints` problems) and `onIssue(DrawingIssue)` (a `PaintIssue`, or a `ShapeIssue` `{ code: 'SUI-RUN-DRAW', path, reason }` for a shape left out); `drawingIssueError(issue)` turns one into the `BuildError` to report. `drawn()` resolves once the last `update` is on screen (after the next frame and any image decoded). `fakeRenderer.ts`: `createFakeRenderer`, a renderer that draws nothing, keeps every tree and answers `hit` and `boundsOf` from `geometry.ts`, for tests.
`svgRenderer.ts` (G1.5): `createSvgRenderer`, registered as `svg` when the module loads. It adds an `svg` (class `svg`, `fill="currentColor"`, a `defs`) to the target and draws each shape as one element with `createElementNS` (`rect` `x y width height rx`, `circle` `cx cy r`, `ellipse`, `line` `x1 y1 x2 y2` from the two points, `polyline` and `polygon` `points`, `path` `d`, `drawText` as `text` `x y text-anchor dominant-baseline font-family font-size` with `textContent`, `g` for `drawGroup` (its `clip` a `clipPath` in `defs`, `clip-path="url(#clip-n)"`) and for `drawRepeat` (G1.5b: its bound copies, its `children`, drawn into it one element per copy at `<repeat>.rows.<recordKey>`, so a changed record rewrites only its element); `drawImage` as `image` since G1.9b, see `images.ts`). Everything is a `setAttribute`, never a `style` attribute. Paint is presentation attributes: `fill` and `stroke` only when set (so a group's reaches its shapes), a token as `var(--ui-…)`, a gradient of `paints` as `url(#paint-<name>)` to a `linearGradient` or `radialGradient` in `defs`, no paint as `none`; `stroke-width`, `opacity`, `stroke-dasharray`, `stroke-linecap`, `stroke-linejoin` only when they differ from SVG's initial value. `rotate`, `scale`, `origin` and the `x`/`y` offset are one `transform="matrix(…)"` from `transformOf`. Every element has `data-shape-path` and `data-shape-kind`, plus the feeder's `attrs`. Events (G1.7): the svg has `pointer-events="none"`; a shape with `interactive: true` gets `role="button"`, `tabindex="0"`, `aria-label` from `_label` and `pointer-events="visiblePainted"` (a feeder's `attrs` override the first three; a feeder must set `interactive` for a shape to take pointer events), and the shapes in an interactive group take the group's. A click on it, or Enter or Space on it, calls `onEvent` with `press`; the pointer entering it, `hover` once per entry; `x` and `y` are drawing units (`getScreenCTM`), the shape's centre for a key or a click with no pointer. The svg's `viewBox` is the caller's, else the `viewBox` property, else the tree's bounds widened by half the widest stroke; `preserveAspectRatio` follows `fit`. A redraw writes only changed attributes and text, removes the elements of shapes that are gone, and moves (never recreates) elements to follow the `children` order. A shape with a set value it cannot draw (text where a number belongs, a word outside the allowed ones, path data that does not parse) or `hidden: true` is left out; the first is reported once as a `ShapeIssue`.
`paint.ts`: colour resolution. `resolveColor(value, read?)` reads a colour value by `colorForm` of `@punyts/stateui-app/core` (the `color` validator's own reading): a literal as it is, a token `{color.accent.base}` as `var(--ui-color-accent-base)` (`tokenProperty`) and, when `read` (a custom property from the scene's computed style) is given, its computed colour, an empty answer meaning the theme lacks it; a paint name is handed back. `buildGradients(paints, paintsPath, read?)` builds the drawing's `paints` (`{ kind: linear | radial, stops: { <key>: { offset, color } }, angle | center }`) into `Gradient`s in bounding-box units (`angle` in degrees, 0 left to right and 90 top to bottom; `center` `[x, y]` or `{ x, y }`, default the middle, radius half the box), stops sorted by offset; `placeGradient(gradient, bounds)` places one on a shape for canvas. `createPaintResolver({ paints, paintsPath, read, onIssue })` gives `resolve(value, shapePath, property)`: a `Paint` (`none`, `color` with `css` for SVG and `computed` for canvas, or `gradient`); an unknown token at run time (`SUI-STATE-TOKEN`), a paint name with no gradient (`SUI-STATE-PAINT`) and a linked value that is not a colour (`SUI-RUN-DRAW`) are no paint and reach `onIssue` once per property path and value (the path the document check `validatePaints` uses), so the feeder reports them with `buildError`. It never throws; `update` rebuilds after a change of `paints` or of the theme.
`drag.ts` (G1.7b): dragging a shape. Pure and Node-tested: `dragAxes(shape)` (the axes of `draggable`, for an `interactive` shape), `dragTo(shapes, path, start, dx, dy)` (a pointer distance in drawing units taken into the parent's coordinates, kept to the axes, clamped), `clampMove` (`bounds`), `stepMove(shape, key, shift)` (arrow keys by `step`, Shift ten times), `withPosition`, `replaceShape` and `lockUnlinkedCopies(shapes)` (a repeat copy with no record path for a drag axis is made not draggable and its repeat listed). `createShapeDrag(host)` runs a renderer's drags: pointer capture, the shape shown moved on every move with no write, `onMove` and then `dragEnd` on release, Escape and pointer cancel put it back, the click ending a drag swallowed, arrow keys as finished moves. Both renderers use it; the contract's `onMove(ShapeMove)` is where the feeder writes, and `ShapeEventName` is `press`, `hover` or `dragEnd` (the shapes' declared names).
`rows.ts`: the row binder of `drawRepeat`, no node per record. `createRowBinder(row, options)` reads the row template once (`row` as the store holds it at `<repeat>.row`, where a `$row` link stays a `<-key`) and `bind(records)` (an array or a keyed map; anything else is none) gives a `RowBinding`: `copies`, one `ShapeTree` per record at `<repeat>.rows.<recordKey>` (inner shapes below it, `children.…`, `clip`), with each property resolved: a value as written, read through `read` (the store's `get`); a `<-prop` link to `$row…` from the record, a missing field leaving the property unset (the shape's default; a value written beside the link is not used); a link to any other target read from the store once per bind. `watch` lists the store paths of those links (resolved through `resolve`, the store's `resolve`) and, with `properties(kind)` (the names a shape declares) and `resolve`, the targets of links the mount applied to the template, which the node object does not show. Node references resolve with `library` and `owner`, as in `resolveRowLinks`; a refused link is in `errors`, a node that is not a shape in `unknown`. `options.renderer` sets the cap (`ROW_CAPS`, `rowCap`: 2,000 SVG, 20,000 canvas; `cap` overrides): the first records up to it are copied and `cut` carries the `SUI-RUN-CAP` error for the feeder to report once. `targetOf(copy, prop)` is the record path a `$row` property came from (`recordsPath`, default `<repeat>.records`, resolved, so a linked `records` gives `$.data.…`), which a drag writes to; a literal or store-linked property has none. `recordKeys(records)` (re-exported from `@punyts/stateui-app/core`, which the dispatcher uses to find a copy's record): array records by distinct `id` (a path segment), else by index; a map by its keys. `copy(key, record, recordKey?)` makes one copy; `bindRows(row, records, options)` binds once. `expandRepeats(shapes, options)` (G1.5b) binds every `drawRepeat` of a shape tree (at the top or in groups; not one inside a row template) and gives the tree with each repeat's copies as its `children`, plus `repeats` (`{ path, binding }`) for the feeder to watch (`recordsPath`, `watch`) and report (`cut`, `unknown`, `errors`); `options.read` is required and gives the raw template at `<repeat>.row` and the records at `<repeat>.records`, the other options are the binder's (`renderer`, `resolve`, `properties`, …). `geometry.ts` takes a repeat's bounds and hits through those copies, as a group's through its children. Pure: no store write, node or link.
`canvasRenderer.ts` (G1.6): `createCanvasRenderer(target, options)`, registered as `canvas`, gives a `CanvasDrawingRenderer` (the contract plus `canvas` and `paint()`, which draws a waiting update at once, for a test that times a draw). It draws the tree into a `canvas` (class `canvas`) with the 2D context: shapes as `Path2D` outlines in their own coordinates through the transforms of `geometry.ts`, paint from `paint.ts` with the colours `computed` (a token read through `read`, the canvas's computed style cached for one draw, `resolver.update({ paints, read })` on every draw), gradients placed on each shape's own bounds (`placeGradient`; an elliptical radial one drawn through a clip in a scaled space), group paint inherited as in SVG (`opacity` multiplied), a group's `clip` as a clip path, `drawText` with `font` read as its custom property (else the page font) and `fontSize` (else the page size), a `drawRepeat`'s `children` (its copies from `expandRepeats`) drawn like a group's. The bitmap size is the canvas's `ResizeObserver` content box times `devicePixelRatio` capped at `MAX_PIXEL_RATIO` (2); the observer draws at once, in the frame, before paint. `update` marks the renderer dirty and asks for one `requestAnimationFrame` per window shared by every canvas renderer; `drawn()` resolves after the draw (or, for a canvas that is never laid out, after two frames). `images.ts` (G1.9b): the pictures of `drawImage`. `imageSourceOf(src)` (a `data:` URL of a png, jpeg, gif or webp picture, or such a file reference; anything else throws `Unusable`, `SUI-RUN-DRAW`), `placeImage(fit, width, height, box)` (where the canvas draws a picture, as `preserveAspectRatio` places it; `cover` is cut to the box), `createImageLoader({ load, release, onSettled })` (one cache per renderer by source: `use` gives `pending`, `ready` or `failed` with a reason and starts a load, `sweep` drops and aborts what no shape used since the last sweep, `settled()` waits for the loads), `loadImageUrl` (SVG: a `data:` URL for `href`, the source's own or built from the file's bytes, decoded through an `img` first) and `loadImageBitmap` (canvas: `createImageBitmap` on a `Blob` of the bytes, or of an `img` decoding a `data:` URL). A file is read with the renderer option `readFile` (the `drawing` raises `ui-file-read`); a read or decode that fails is a `ShapeIssue` `SUI-RUN-FILE`. `canvasPath.ts`: `buildPath(commands, sink)` builds a path from the parsed command list of `parsePathData` into a `PathSink` (a `Path2D`, or a recorder in tests): relative to absolute, `H`/`V` as lines, `S`/`T` reflected, `A` as an `ellipse` segment through `arcCenter` (SVG 2 B.2.4; a radius of 0 is a line). `shapeReader.ts`: `ShapeReader` (the property checks of the SVG renderer: `number`, `word`, `points`, `numbers`, `text`, `pathCommands`, `fontProperty`, `transform`), `Unusable` (its reason becomes the `SUI-RUN-DRAW` text), `ANCHORS`, `BASELINES`, `CAPS`, `JOINS` and `contentBox(shapes)` (the tree's bounds padded by half the widest stroke, what a drawing with no `viewBox` fits). `svgRenderer.ts` reads through it too.
`scheduler.ts` (G1.8): motion, no DOM of its own. `createScheduler(host)` is one animation-frame loop per renderer (`host` gives `requestFrame`, `cancelFrame`, `now` and `onFrame(changed)`, so tests drive it with a fake clock): `tween(key, from, to, timing)` (a key that is already tweening starts from its current value), `valueOf`, `cancel`, `keys`, `request(task)` for frame tasks, `setReduced` (on: every tween ends at its value and every later one jumps), `idle` (no tween, no task, no frame asked for), `settled()` and `dispose`. The parsers read the theme's motion tokens: `parseDuration` (`ms`, `s`, a bare number as milliseconds; `0ms`, `0s` and `0` are all 0), `parseCubicBezier`, `cubicBezier`, `parseEasing` (also the CSS keywords), `durationToken` and `easingToken` (the theme's `--ui-motion-duration-*` and `--ui-motion-easing-*`, else `DEFAULT_DURATIONS` and `DEFAULT_EASINGS`, the shipped values) and `isReducedMotion(read)` (`REDUCED_MOTION_PROPERTY`, `--ui-motion-duration-base`, parses to 0). `transition.ts`: `createTransitions({ scheduler, read, normalize? })` takes each new tree (`apply`) and tweens a changed number, or a `fill` or `stroke` colour (`COLOR_PROPERTIES`; literal or token, `parseColor`, `formatColor`), of a shape with `transition`; any other change jumps, and `current()` is the tree with the running tweens at their values. `settle(path, values)` puts values on screen at once, which `settleMoves` does for a drag's `onMove`, so a dragged shape is not tweened back. `styleReader` and `tokenNormalizer` are the renderers' readers of custom properties and of colours the parser does not know. Both renderers use them. `animate.ts` (G1.8b): `createAnimations(scheduler)` plays each shape's `animate` (`spin`, `pulse`, `fade`, `blink`; `readAnimation`, `animatedProperties`) as one frame task of the scheduler: `follow(tree)` on each update, `decorate(tree)` in each frame, `paths()` for the shapes a frame redraws. No task while no shape animates, none while motion is reduced (the shapes rest), and nothing is written to the store.

## paint/
The painting engine of `paintField` (G2.6; the field of G2.7 draws with it and G2.8 saves what it holds): brush, eraser, undo, redo and clear, with no DOM or store state, tested in Node with a fake raster (`test/harness/fakePaintCanvas.ts`) and in Chromium. `strokes.ts`: the stroke model (`Stroke`: `tool`, the resolved `color`, `size`, `points` in canvas pixels), `PAINT_TOOLS` (`brush`, `eraser`) and `isPaintTool`, `strokeColor(value, read?)` (a literal, or a token read through `resolveColor` of `drawing/paint.ts`; the stroke keeps the colour it resolved, so a theme switch does not recolour old strokes), `clampPoint` and `addPoint` (into the canvas, a repeat of the last point left out), and `createPaintLog({ limit, onFlatten })`: the command log (`push`, `clear` as an undoable entry, `undo`, `redo`, `reset`, `blank`) over a bounded stack of `UNDO_LIMIT` (200) entries whose oldest go to `onFlatten` for the base bitmap. `draw.ts`: `smoothPath` (quadratic curves through the midpoints, so it stays inside the canvas), `drawStroke` (round caps and joins, one path per stroke; the eraser is `destination-out` down to transparent, so the field's background lies under the canvas and is composed in when saving), `PaintContext2D` (the part of a 2D context it uses) and `createPainter({ context, width, height, createSurface?, read?, limit? })`: `begin`, `extend`, `end`, `cancel`, `undo`, `redo`, `clear`, `reset`, `render`, `dispose`, `blank`, `canUndo`, `canRedo`. It keeps the committed painting and (from the first flatten) the base bitmap off screen, so 200 undos after 250 strokes give the bitmap after stroke 50 pixel for pixel. `size.ts`: `clampDimension` (`width` and `height` to 1..4096, else a fallback), `clampBrushSize` (1..200), `clampSizes` (a sane `sizes` list: numbers, clamped, no repeats, at most 12, else `DEFAULT_SIZES`) and `pickSize`.
