# Changelog

## Unreleased
- **Docs** (S1.9): the README's Search keys section names `category`, `purposes` and the composed `summary`, the build's `requireSearchKeys`, and the errors a missing or repeated key raises (`SUI-BUILD-CATEGORY`, `SUI-BUILD-PURPOSES`, `SUI-BUILD-SUMMARY`, `SUI-BUILD-PURPOSE-DUPLICATE`).
- **Docs** (O1.11): the `outlet` section points to how apps with screens are assembled and mounted (`assembleApp`, `navigate`, `$.route`, `MountOptions.route`, `MountOptions.instance`).
- **Screens from links and the nav** (O1.8): `link` and `menuItem` take `screen` (string) and `params` (object); with a `screen` a click raises `sui-navigate` before `press`, and `link` points at `#/{screen}`. `nav` sets `active` to the item whose `screen` is `$.route.screen` and leaves `active` to the route on a press of such an item. The test harness mounts with `MountOptions.route: false`, so tests leave the page's URL alone. Tests in `test/atoms/link.browser.test.ts` and `test/composites/page-nav.browser.test.ts`.
- **`outlet`** (O1.7): the composite the shell shows its screens in. A `section` with a `slot` for the screen containers `mountApp` appends; content `_label` (German overlay); on a change of `$.route.screen` focus moves to it. Category `navigation` with three purposes. The test harness's `mountComponent` takes `screens` and `start` (the component is then the shell) and returns `navigate(screen, params?)`. `test/catalog.test.ts` counts it among the later composites.
- **Search keys for the composites and composed components, now required**: all 23 composites have a `category` and three or four `purposes`, and the eight composed files have a one-line `summary`, a `category` and `purposes` that name the whole job (`crudTable`: "edit records in a table", not the phrases of `table`). From the design table: `page`, `panel`, `splitPane` and `dashboardGrid` are `layout`; `nav`, `tabs` and `menu` are `navigation`; `form` is `forms`; `table`, `list`, `recordGrid`, `tree`, `board`, `calendar` and `chart` are `data`; `modal`, `drawer`, `popover` and `confirmDialog` are `overlays`; `messageList` and `chatView` are `conversation`. Assigned here: `accordion` and `toolbar` are `layout` (they arrange other components), `recordList` and `tableRow` are `data`, `toastRegion` is `feedback`, `crudTable` and `masterDetail` are `data`, `formDialog` and `wizard` are `forms` (they collect input), `settingsPage` is `layout`. `scripts/buildComponents.mjs` passes `requireSearchKeys: true`, so a component without `category` or `purposes`, or a composed file without `summary`, fails the build. Every catalog entry now carries both keys.
- **Search keys for the molecules**: all 26 molecules have a `category` and three or four `purposes`. Every `*Field` and `searchBox` is `forms`; `breadcrumb`, `pagination`, `stepper` and `menuItem` are `navigation`; `stat` and `descriptionList` are `data`; `alert`, `toast` and `emptyState` are `feedback`; `card` and `avatar` are `content`. Assigned here because the design table does not name it: `disclosure` is `layout` (it arranges a section that opens and closes). `dateRangeField` and `stepper` carry the phrases the search tests use. `test/catalog.test.ts` checks the keys, the categories above and those phrases.
- **Search keys for the atoms**: all 18 atoms have a `category` and three to eight `purposes` (what a person uses the component for), which the catalog carries for search. Categories from the design table: `badge`, `progress`, `spinner` and `skeleton` are `feedback`; `button` is `forms`; `tooltip` is `overlays`; `text`, `markdown`, `image`, `icon` and `divider` are `content`. Assigned here because the table does not name them: `input`, `textarea`, `checkbox`, `select`, `switch` and `segmented` are `forms` (they take a value from a person), and `link` is `navigation` (it moves between screens). `test/catalog.test.ts` checks every atom has both keys and no phrase made only of the words of its own name.
- **Test fixes**: the component token test accepts an `inset` default of two to four references (`panel.padding`, `tabs.padding`), and `test/image.test.ts` passes `parseShape` a library-relative path, so it no longer fails on Windows.
- `panel` takes `padding` (`md` default, `none`, `sm`, `lg`): `none` makes a layout-only box without touching the `panel.padding` token, which a node theme passes on to every nested panel. The `panel.padding` and `tabs.padding` tokens are insets (`{space.inset.md} {space.inset.md}`), so a theme may give two values.
- `image` paints its backdrop with the new token `image.fill` (default `{color.surface.sunken}`), which `ui_component_get` lists, instead of a fixed colour; set it to `transparent` in a node theme for a cut-out picture.
- `recordList` (and so `list`, `table`, `tree`) reports `SUI-RUN-CLIPPED` once when the first row's content is taller than the row, naming the row height and the height it needs, instead of cutting it off silently.
- `stat`, `table` columns (through `tableRow` cells) and `descriptionList` items take `fractionDigits` (0 to 20), as `chart` does: `format: "currency"` with `fractionDigits: 0` shows `$1,299`.
- `nav` takes `overflow` (`wrap` default, `scroll`): a horizontal nav with `scroll` keeps its items on one row that scrolls sideways on a narrow screen instead of wrapping.
- `chart` takes `fractionDigits` (integer 0 to 10, unset by default): it fixes the digits after the decimal separator of every value the chart formats, that is the value axis ticks, the tooltip, the hidden data table and the donut slice labels and total, so `format: "currency"` can drop the cents ("$12,346"). Unset, values keep the locale's own digits. Donut shares keep their own percent format. The shared `formatValue` gains the matching option `fractionDigits` for `number`, `percent` and `currency` (`duration` ignores it; an invalid count is ignored). The chart summary served by `ui_component_get` (limited to one line of 120 characters) mentions it, and the property shows with its 0 to 10 range. Tests in `test/format.test.ts` and `test/composites/chart.browser.test.ts`.
- `panel` summary (the one-line text `ui_component_get` serves; the shape format has no longer description) now says plainly that the default is flat and borderless, with no border and no shadow, and that `bordered: true`, `elevation: "raised"` or both give a card look. The default is unchanged: `panel` is the structural container of `messageList` rows, `wizard`, `chatView`, `masterDetail`, `crudTable` and the `form` actions, which would all gain borders and shadows, and tests assert the flat default. The README entry leads with the same statement; `test/composites/panel-toolbar.browser.test.ts` already covers the flat default, `bordered` and `elevation: raised`.

## 0.1.0
- `page` collapses a `navPosition: "start"` nav on narrow pages: new `navBreakpoint` (px, default 768, 0 disables), `navOpen` (default false, reflected), runtime `compact` (reflected) and content `_navLabel` (`Menu`, German `Menü`). A compact page shows a bar with a menu button (`aria-expanded`, `aria-controls`) and the nav as a panel under it while `navOpen`; the main area uses the full width. Escape, a press outside, a `select` or `press` in the nav, and growing past the breakpoint close it. Desktop layout is unchanged. Tests in `test/composites/page-nav.browser.test.ts`.
- `rowHeight` takes `xl` on `recordList`, `list` and `tree` (1.5 times the large control height) for two-line rows. The `recordlist.row` token does reach the body of a `list` through the node's `theme` (`"theme": { "recordlist": { "row": "72px" } }`), but only while `rowHeight` is `md`: `sm`, `lg` and `xl` set `--sui-row-h` themselves. Documented in the README; tests in `test/composites/list.browser.test.ts`.
- `stepper`: an `active` value that names no step (an order status such as `Cancelled`) leaves no step current instead of marking the first; an empty `active` still means the first step, completed steps stay done. `currentStep` in `src/shared/steps/steps.ts` returns an empty key for it.
- The default `_placeholder` of `input`, `textarea`, `textField` and `textareaField` is empty (it was `Type here`), and their German overlays no longer translate it. The element is rendered with `placeholder=""`, which shows nothing.
- `segmented`: options already take an optional `icon` (with or without `iconOnly`); a test now covers an icon beside the label.
- `recordList` copies its window to the articulation property `window` (`{ first, count }`), and `list` and `table` pass it up to their own `window`, so app logic can watch it and fill the window with `query` (`items` and `total`). Writing `window` does not scroll.
- `modal` is centred in the viewport: the shared `overlay.css` sets `margin: 0` on the dialog, which cancelled the user agent's auto margins of a modal dialog, so every modal opened in the top-left corner. The modal sets `margin: auto` again; the drawer keeps its own inset placement.
- `recordList` `rowHeight` sizes the rows: `sm` and `lg` set `--sui-row-h` to the small and large control heights times the density factor (`md` keeps the `recordlist.row` token). The property was declared and reflected but had no style. `list` and `tree` take `rowHeight` (`sm`, `md` default, `lg`) and pass it to their body, so a row template taller than a control fits.
- A `toolbar` or `panel` in a `form`'s `actions` slot fills the row, so its own alignment applies: the wizard's `align: end` toolbars put Next and Finish at the end instead of the start.
- `table` grows to its rows where it has no definite height: the record list sat absolutely inside the body, so in a scrolling page the table kept its three-row minimum and scrolled 11 rows inside 108 px. The body is now a grid with the list in flow, which grows to the rows in an auto-height container and fills and scrolls in a definite one (still at least three rows tall). `recordList` caps its scroller at `100dvh`, so a list that grows to its rows stops at the viewport height and renders only the rows in view; a definite container taller than the viewport shows the list at the viewport height. `test/composites/table.browser.test.ts` covers growing, the minimum, filling, scrolling and the cap.
- A hidden record view keeps its rows: hiding a `recordList`, `board`, `recordGrid` or `chart` (its section or tab set to `display: none`) shrank the viewport to nothing, so the window went to zero rows, every pooled slot was unbound, and showing it again bound them all once more (about 1 s for a board of several columns). The resize observers (`createViewportObserver`, `createGridViewport`, `createSlotMeasure`, the board card probe and the chart plot) now ignore an entry with an empty content box (new export `isUnrendered`), so the last window, measured heights and drawing stay. `test/composites/record-list-viewport.browser.test.ts` hides and shows a list and checks the window and rows are unchanged.
- `tree` rows indent and show an expand glyph in a JSON document: the `recordList` slot of the `tree` role pads its start by `--sui-level` times `--sui-indent` and draws an `aria-hidden` chevron (`chevron-right`, `chevron-down` when open, mirrored in right-to-left text) for records that have or may have children, with a gutter on leaves so rows align; pressing the chevron toggles the record and the pending placeholder keeps the same indent. A row template no longer indents itself. `test/composites/tree-indent.browser.test.ts` covers indent, alignment, flip, RTL and press.
- `masterDetail`: the master list was about 15 px wide because the `region` layout sizes the `w` column to its content and a pooled list has almost no intrinsic width. It is now a three-column `grid` (list one column, detail two) that stacks below `md`. `test/composed/master-detail.browser.test.ts` checks the master is at least 200 px in a 1000 px container and full width below the breakpoint.
- `icon` honours a static `name` (and `filled`) attribute when it shares its parent's scope: `<ui-icon name="chevron-left" size="sm">` in a component view drew nothing because the icon read `<host basePath>.name`. An icon with a `state` attribute still reads its own state. `test/icons/icon-glyphs.browser.test.ts` mounts every catalog example and asserts no `ui-icon` in any shadow root has an empty glyph.

Paragraphs, ATX and setext headings, bullet and ordered lists with nesting and lazy continuation, block quotes, fenced and indented code, horizontal rules; a raw HTML block becomes a `text` block. Linear in the input (no regular expression on the text), with containers capped at `MAX_BLOCK_DEPTH`; a 20,000-character pathological input parses in well under 50 ms. The `markdown` component follows in E8.35.
- Markdown inlines, tables, link safety and `parseMarkdown` (E8.34), in `src/shared/markdown/` and exported from the package: `parseInline` (emphasis and strong by the CommonMark delimiter algorithm, inline code, links, `https:` autolinks; an image becomes its alt text and inline raw HTML its characters), `safeHref` (a link keeps its target only for `#`, relative in-app targets and `https://`; `javascript:`, `data:`, `http:`, `mailto:`, `//host` and spellings with control characters, whitespace or entities leave the link text as plain text), GFM tables with column alignment, and `parseMarkdown(source, { profile, maxLength })` returning `{ children, truncated }` with every node holding `type`, `children`, `text`, `href`, `level` and `align`. The source is cut at a block boundary at `maxLength` (default 20,000). Linear, no regular expression on the text; a 20,000-character pathological input parses in a few milliseconds.
- `markdown` atom (E8.35): `profile` (`basic`, `inline`; reflected), `headingOffset` (default 1, headings capped at `h6`), `maxLength` (default 20,000; cut at a block boundary, the host gets `data-truncated`), content `_text` (German overlay), event `press` (`{ href }`), tokens `gap` and `code.background`. It renders the `parseMarkdown` tree with `createElement` and `textContent` (`src/shared/markdown/render.ts`) and has no HTML path (a test greps the sources and the built markdown chunk for `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `DOMParser`). A link is a `span` with `role="link"`, a tab stop and no `href`, kept for `#`, relative and `https:` targets only; a click or Enter raises `press` with the `href` and nothing navigates or opens. Typography comes from the text roles, so the dark and contrast overlays apply. `cutPoint` now cuts at the end of the last block that fits whole.
- `recordGrid` commands and following the end (E8.19, AMM-1799): commands `scrollTo` (a record key) and `scrollToEnd`, the articulation `follow` (stay at the end while records are added, a height changes or the viewport is resized, unless the user scrolled up) and the runtime property `atEnd`; the scroll the grid makes itself is not read as the user leaving the end.
- `messageList` composite (E8.19, AMM-1799): a one-column `recordGrid` with measured heights that stays at the newest message while records are added or the last one grows, unless the user scrolled up; then a "New messages" button (`_newMessages`, `de` overlay) appears and takes the view to the end. Data `records`, slot `row` (default: an `avatar`, a `markdown` body and the time), command `scrollToEnd`, runtime `pinned` and `unread`, tokens `new.fill` and `new.on` (group `messagelist`). Streamed replies are one record rewritten per chunk (design decision recorded in the UI builder design).
- `chatView` composed component (E8.20, AMM-1800): a `panel` with a `messageList` and a composer `toolbar` (an auto-growing `textareaField` and a Send `button`). Send and Enter run `emit chat.send` with the typed text and clear the field, Shift+Enter adds a line, an empty composer sends nothing. Exposes the messages link, the composer placeholder, the send event name and the button text. German overlay.
- `textareaField`: the `sendOnEnter` articulation (default false), the `send` command and the `send` event (the trimmed text); needed because an `emit` carries the payload of the event that ran it, and a button press has no text.
- `fileField` molecule (E8.22, AMM-1802): a field on the field base whose `value` is a list of file references `{ id, name, size, type }` (never bytes), with `accept` (narrowed to the ADR-0017 types), `maxSize` (default and maximum 10 MiB; more is `SUI-STATE-INVALID`) and `maxFiles` (default 1). Files arrive by picker or drop, type, size and count are checked before transfer (rules `accept`, `maxSize`, `maxFiles`), and each file goes to the host through the `ui-file-transfer` event that the `@punyts/stateui-app` dispatcher answers with `hooks.transferFile`. Rows show progress, a remove button aborts a transfer through the hook's `signal`, and a rejected transfer's code (`too_large`, `unsupported_type`, `quota`, `offline`, ...) is the field error. English and German messages; shared code in `src/shared/field/files.ts`; the test harness `hooks` accept `transferFile`.
- `fileField` follow-up (E8.22): an `accept` entry outside the allowed list is reported once per distinct entry as `SUI-STATE` through `report.warning` (and still ignored), and a reset (the command or a form) aborts the transfers under way. `createField` gained the option `onReset`, which only a field that passes it uses.
