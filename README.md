# @punyts/stateui-components

The StateUI component library: atoms, molecules, composites and composed components, built with `@punyts/stateui-app`.

## Layout
- `components/atoms/`, `molecules/`, `composites/`, `composed/`: one folder per component, by the `@punyts/stateui-app` file convention. The group folders are grouping only; `npm run build` creates them when they are missing, because git does not keep empty folders. Nothing but component files may sit in `components/`, so tests live in `test/`.
- `src/shared/`: CSS partials and base controllers used by several components.
- `scripts/`: `build.mjs` (the `npm run build` step) and `buildComponents.mjs` (`buildLibrary` plus the `register` helper).
- `test/`: the harness (`test/harness/`) and the fixture component `probe` (`test/fixtures/components/atoms/probe/`). The fixture is test-only and never part of `dist/`.

## Build
`npm run build` compiles `src/` with `tsc`, then runs `buildLibrary` over `components/` into `dist/components/` (modules, `catalog.json`, locale overlays, `index.js`) and writes `dist/register.js`. It then runs `scripts/build-icons.ts`, which writes `dist/icons.json` (Tabler icon names, categories, tags, outline and filled path data, and the alias table from `src/icons/aliases.ts`) from the pinned `@tabler/icons` devDependency; `brand-*` icons are left out. Tabler's licence is in `LICENSE-tabler-icons`.

## Search keys
Every component carries the two keys the server's `ui_components_search` reads: `category` (one of `layout`, `navigation`, `forms`, `data`, `feedback`, `overlays`, `content`, `conversation`, `graphics`) and `purposes` (three to eight short phrases of what a person uses the component for, not the words of its name). A composed file also declares a one-line `summary`. `scripts/buildComponents.mjs` builds with `requireSearchKeys: true`, so a missing key fails the build: `SUI-BUILD-CATEGORY`, `SUI-BUILD-PURPOSES` or `SUI-BUILD-SUMMARY`. A purpose phrase that repeats another component's is `SUI-BUILD-PURPOSE-DUPLICATE`. The rules live in `@punyts/stateui-app` (its README, under Building a component library); `test/catalog.test.ts` checks every entry has both keys.

## Patterns
Ready screens and shells live in `patterns/<kind>/<name>/<name>.pattern.json` (kind `screen` or `shell`); the build (`scripts/buildComponents.mjs`, which passes the folder as `patternsDir`) checks them against the components and lists them in the catalog's `patterns`, where `ui_patterns_search` of `@punyts/stateui-mcp` finds them by a need in plain words and `ui_app_create` and `ui_screen_create` copy them (the format and checks are in the `@punyts/stateui-app` README, under Patterns). Each has `slots` (the nodes an agent fills) and `params` (a title and the dataset paths, written into the tree by `applyPattern`).

## Theme presets
Four moods to start a theme from live in `presets/<name>.preset.json`: `clean`, `moody`, `professional` and `playful` (the owner's table of search-first epic 2, S2.7, with amber.700 and teal.700 in light mode for 4.5 contrast). The build checks them (`presetsDir`, see the `@punyts/stateui-app` README) and lists them in the catalog's `themePresets`; `ui_theme_create` copies one by name. Colours that differ by mode are in each preset's own `light` and `dark` mode overlays, which refine the shipped modes of those names; the base holds type, radius, density and motion. A theme cannot set its default mode, so `moody`'s summary asks for the app mode `dark`. Tests: `test/themePresets.test.ts` in stateui-mcp (valid themes, body text passing 4.5 in every mode, any two presets differing).

## Package exports
- `.`: `COMPONENT_GROUPS`, and the server-side icon helpers: `isIconName` (the `isIconName` option of `validateNode`; reads `dist/icons.json`, names and aliases), `createIconNames` and `loadIconsFile` (the same lookups over any `icons.json`), `validateIconNode` (the `SUI-STATE-FILLED` warning), `CORE_ICON_NAMES` and `ICON_ALIASES`.
- `./components`: `components`, `componentTokens` and `registerAll()`.
- `./components/*`: a built module, controller or locale overlay.
- `./catalog.json`: the component catalog.
- `./icons.json`: the icon data the server reads (never part of the runtime bundle).
- `./register`: `register(window)` defines every component on the page. StateUI defines elements on the global registry, so `window` must be the page's own; it throws otherwise, and a component that is already defined is skipped.

## Atoms: `text`, `link`, `divider`, `image`
- `text`: `_text`, shared `tone` and `textRole` (default `body`), `align` (`start`, `center`, `end`), `truncate` (lines; 0 means no clamp) and `element` (`span`, `p`, `h1` to `h6`). The tag is chosen by an `if`/`ifelse` chain in the view, so changing `element` swaps the tag and `element: "h2"` stays an `<h2>` whatever the `textRole`.
- `link`: `_text`, `tone` (default `accent`) and `href` (a `url` property: `#` and relative targets; `http:`, `javascript:` and `//host` are `SUI-STATE`). A click or Enter raises `press` once, with `{ href }` as detail; the click is cancelled, so the link never navigates by itself and the application decides with `on`. A `pattern` validator (`^(?!data:|https:)`) also refuses `data:` and `https:` hrefs, so a link stays in the app. A link with a `screen` (and `params`, an object) points at `#/{screen}` and on a click first raises `sui-navigate` with them, so an app with screens shows that screen (O1.8); `press` still follows.
- `divider`: `orientation` (`horizontal`, `vertical`) and `_label`, shown in the line only when not empty. The line is `role="separator"` with `aria-orientation`, named by the label when there is one.
- `image`: `src` (a `url` narrowed to `data:` and `https:` by a `pattern` validator; a `data:` image may be at most 10000 characters, and the host page must allow `https:` images, as stateui-mcp's runtime page does), `_alt` (required unless `decorative`), `fit`, `ratio` and `radius` (mapped to `--ui-radius-*`).

## Atoms: `markdown`
- `markdown` (E8.35, folder `components/atoms/markdown/`): formatted text from Markdown source. `profile` (`basic`: paragraphs, headings, emphasis, lists, block quotes, inline and block code, links, rules, tables; `inline`: emphasis, code and links only, laid out inline; reflected), `headingOffset` (default 1: `#` is an `h2`; capped at `h6`), `maxLength` (default 20,000; a longer source is cut at a block boundary and the host gets `data-truncated`); content `_text` (the source, usually linked, translated like any content); event `press` (payload: `{ href }`); tokens `gap` (between blocks) and `code.background` (group `markdown`).
- The parser is the library's own (`parseMarkdown`, exported from the package) and the controller builds the DOM with `createElement` and `textContent` (`src/shared/markdown/render.ts`): there is no HTML path, a raw tag in the source is shown as its characters, an image is its alt text, and a test greps the sources and the built markdown chunk for `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `DOMParser`. A link is a `span` with `role="link"`, `tabindex="0"` and no `href`, kept only for `#`, relative in-app and `https:` targets (any other target leaves the link text as text); a click or Enter raises `press` with the `href` and nothing navigates or opens. The app may connect `press` to an `emit` with `on`.
- Typography comes from the text roles, so the dark and contrast overlays apply: `h1` `display`, `h2` `title`, `h3` and `h4` `heading`, `h5` `label`, `h6` `caption`, text and lists `body`, code `code`; table header cells use `label`. The link colour is the semantic `color.focus` (the component has no `tone`).

## Atoms: `segmented`
- `segmented` (E8.29, folder `components/atoms/segmented/`): shared `size`; `options` (keyed map of `_label` and `icon`; the key is the value), `multiple` (default false), `disabled`, `iconOnly` (reflected), data `value`, content `_label` (the group's name, default `Options`); event `change` (payload: the new value, raised for a press or an arrow key, not for a write to `value`); command `focus`. Tokens, group `segmented`: `radius` and `padding.inline`.
- Single: `role="radiogroup"` of `role="radio"` buttons with `aria-checked`; `value` is the chosen key (empty for none), and pressing the chosen segment changes nothing. The chosen segment (else the first) is the only tab stop; Arrow Left and Right (swapped in right-to-left), Up and Down move focus to the next or previous segment and choose it, wrapping. Multiple: `role="group"` of buttons with `aria-pressed`, all in the tab order, each press toggles its key, and `value` is written as an array in option order (a value that is not an array counts as empty). `disabled` disables every segment.
- `iconOnly` hides the label of each option that has an icon and sets it as the button's `aria-label`; the label is also its tip (the shared `tip="iconOnly"` directive, on while `iconOnly` is true; each segment is its own `anchor-scope`, so the tip sits above its own segment). An option with no icon keeps its visible label. The tip elements are always rendered (a mixin cannot run on an element under `if`) and are empty, and so hidden, when `iconOnly` is off.

## Icons: `icon`
- `icon`: `name` (type `icon`; empty draws nothing), `filled` (false), `decorative` (true: the glyph is `aria-hidden`; false: `role="img"` named by `_label`, which `requiredWhen` makes required), shared `tone` (no default: without it the icon takes the surrounding text colour) and `size` (default `md`, from `--icon-size`). The line weight is the default semantic token `icon.stroke` (`--ui-icon-stroke`, default 2); it applies to outline icons only, so a write to `$.theme.tokens.icon.stroke` changes every outline icon.
- Drawing: the `icon-paths` mixin (registered by `icon.controller.ts`) builds an `<svg>` with `createElementNS` from path data, never from markup, and redraws when `name`, `filled` or `$.runtime.icons` change. A path is a string `d`, or `{ d, fill?, stroke?, opacity? }` for the 82 Tabler paths that carry their own style (`fill: true` fills with the current colour, `stroke: false` draws no line). Outline icons are stroked with `currentColor`, round caps and joins; filled icons are filled with `currentColor`. `filled: true` on a name with no filled variant draws the outline.
- Lookup order: `$.runtime.icons[name]`, `$.runtime.icons[alias target]`, then the core set by the same two keys. A runtime entry is `{ outline: path[], filled?: path[] }` (the shape of an `icons.json` entry without category and tags); an entry that is not that is ignored. A name found nowhere draws nothing and is reported once through `@punyts/core` as `SUI-RUN-ICON`.
- Core set: `src/icons/coreNames.ts` lists the icons the library's own components use. `scripts/core-icons.ts` reads their path data from the pinned `@tabler/icons` and `buildComponents` writes it as `icons/core.js` (and `core.d.ts`) beside `components/`, in `dist/` and in each test build; the controller imports `../icons/core.js`. A test fails when a shape default or a `<ui-icon name="...">` in a view uses an icon outside the set.
- Validation: `isIconName` gives `SUI-STATE-INVALID` for an unknown name; `validateIconNode(node, statePath)` gives the `SUI-STATE-FILLED` warning, which the shape format cannot express. The server runs both beside `validateNode`.

## Actions: `button`
- `button`: shared `tone` (default `accent`), `variant` (default `solid`) and `size`; `icon` (type `icon`), `iconPosition` (`start`, `end`, `only`; reflected), `disabled`, `busy`, `fill` (reflected; stretches to the container) and `_title`. Tokens `radius`, `padding.inline` and `gap` (group `button`).
- Variants paint only from `--tone`, `--tone-soft` and `--tone-on`: `solid` fills with the tone, `soft` with the soft tone, `outline` has a tone border and no fill, `ghost` has neither, `link` looks like underlined text with no padding.
- `press` (no detail) fires once per click, Enter or Space, and not while `disabled` (native `disabled`) or `busy` (the button stays focusable). The `focus` command focuses the native button. With `iconPosition: "only"` no label is drawn and `_title` is the `aria-label`. It also shows `_title` as a tip (see Tips).
- `busy` draws a spinner from the button's own CSS over the content, which stays laid out but hidden, so the width does not change. Its duration is a `--ui-motion-duration-slow` multiple, so `motion: "reduced"` stops it.
- The icon is drawn by the `icon-paths` mixin of `icon`, whose attribute value names the property that holds the icon name (`icon-paths="icon"`; empty means `name`). It inherits `--icon-size` and the text colour from the button.

## Bare controls: `input`, `textarea`, `select`, `checkbox`, `switch`
Both `@include "control.css";` from `src/shared/css/` (inlined by the build's `sharedCssDir`, then linted). `input` has shared `size`, `disabled`, `readonly`, `required`, `inputType`, `min`, `max`, `step`, `maxLength`, `_placeholder`, `_label` (accessible name) and `value`; it raises `change` (blur or Enter) and `input` (each keystroke) and takes the `focus` and `clear` commands. `textarea` adds `rows` and `autoGrow`. Typing writes `value` through `bind`, so a `<-value` link writes `$.data`; `inputType: "number"` writes a number. Tokens `radius`, `border` and `padding.inline` are in the group `control`, with `selected.fill` and `selected.on` (the checked colours of `checkbox` and `switch`).

### `select`, `checkbox`, `switch`
The same `control` token group and the same `size`, `focus` and `clear`. `select` takes `options`, `optionValue` (`value`), `optionLabel` (`label`), `multiple`, `value`, `disabled` and `required`. `options` is a data array (normally `"<-options": "$.data.statuses"`; its labels are not translated) or a keyed map `{ "open": { "_label": "Open" } }` whose key is the value and whose `_label` is content, so a locale overlay translates it; an entry that holds `_label` is treated as a map entry. The value is the option value as the data holds it (a number stays a number); with `multiple` it is an array. The chevron is drawn with CSS. `checkbox` and `switch` have `checked` (written through `bind`), `disabled`, `readonly` (a click or Space changes nothing), `required` and `_label` (accessible name); `switch` has `role="switch"` and `aria-checked`. Each raises `change` with the new value, after the data is written; `clear` sets `false` (`select`: `""` or `[]`).

## Molecules: `stat`, `avatar`
- `stat`: shared `tone` (none by default) and `size` (`sm`, `md`, `lg` set the figure's type role); `format` (`number`, `percent` from a 0 to 1 value, `currency`, `duration` from seconds as `m:ss` or `h:mm:ss`), `currency` (an ISO 4217 code, no default, required through `requiredWhen` when `format` is `currency`), `trend` (`up`, `down`, `flat`), content `_label` and `_unit`, and data `value` and `delta` (a number or numeric text; no value shows a dash). The shared formatter `src/shared/format/format.ts` formats with `Intl` for `$.locale`, so a data write or a language switch reformats. The controller writes the runtime properties `shown`, `deltaShown` (signed) and `trendIcon` (`chevron-up`, `chevron-down`, `minus`), which the view shows; the glyph is drawn by the icon component's `icon-paths` mixin, and it takes the tone colour only when `tone` is set. `tone` colours the change line (delta and glyph) only, never the figure or the label, so a red headline number is not the way to say a value is bad: give the change a `danger` tone, or the card around it.
- `avatar`: shared `size` (the control height), `shape` (`circle`, `square`), content `_name` and `src` (a `url` narrowed to `data:` and `https:` by a `pattern` validator). The picture shows when `src` is set; otherwise the initials of the first and last word of `_name` (one word gives one letter), written by the controller into the runtime property `initials`. The element is `role="img"` with `_name` as its label.

## Messages: `alert`, `emptyState`, `toast`
- `toast` (E4.27, folder `components/molecules/toast/`): a transient message that `toastRegion` (E5.22) creates and removes. Shared `tone` (default `neutral`); `icon` (empty means the default of the tone, as for `alert`, from `src/shared/tone/toneGlyph.ts`), `dismissible` (default true), content `_title`, `_text` and `_closeLabel`, the slot `action` (a node, drawn with `<sui-node>`, for an Undo button). `danger` and `warning` use `role="alert"`, the others `role="status"`. The close button raises `close` and nothing else: a toast has no `open` state, its owner removes the node.
- `alert`: shared `tone` (default `info`) and `variant` (default `soft`); `icon` (empty means the default of the tone: `info-circle` for `info`, `neutral` and `accent`, `alert-circle`, `alert-triangle` and `circle-check` for `danger`, `warning` and `success`), `dismissible`, `open` (default true; reflected, and a closed alert is `display: none`), content `_title`, `_text` and `_closeLabel` (the accessible name of the close button, so it has a German overlay) and the slot `actions` (a node, drawn with `<sui-node>`). `danger` and `warning` use `role="alert"`, the others `role="status"`. The close button (shown when `dismissible`) and the `close` command write `open: false` and raise `close` once; the `open` command writes `open: true`. The runtime properties `glyph` and `closeGlyph` hold the icon names the view draws with `icon-paths`.
- `emptyState`: `icon` (none by default), content `_title` and `_text` and the slot `actions`; the icon, title, text and actions are each drawn only when set.

## Fields: `textField` (the field base)
- Folder `components/molecules/text-field/` (kebab, as the convention requires; the component is `textField`, the tag `ui-text-field`). `textField` has `_label`, `_placeholder`, `_help`, `icon`, `disabled`, `readonly`, `inputType` (`text`, `email`, `password`, `url`, `tel`, `search`), `value`, shared `size` (default `md`) and `density`, `titlePosition` and `width`. Typing writes `value` through `bind`, so a `<-value` link writes `$.data`.
- `titlePosition` (`top` by default, `left`, `inner`, `hidden`) is `reflect: true`, so it is the host attribute `title-position` and the stylesheet lays out from it: `top` puts the label above, `left` in a column of `label.width` beside the control, `inner` over the top-left corner inside the control box (the control gets room for it), `hidden` clips the label to one pixel so it stays the control's accessible name (`<label for>`). `width` is `fill` (default), `auto` (fit the content) or a whole number of `ch` for the whole field; a value that is none of these means `fill` (a shape validator cannot express a union of words and a number).
- Help and error: the control's `aria-describedby` names `help` and `error` only while their text is shown. The error sits in a `role="status"` `aria-live="polite"` wrapper that is always in the DOM, so a message that appears is announced. `error` (the failing rule's name, empty for none) is a runtime property, as is `message` (the text of `_errors` for that rule, kept by the controller because a binding on a map does not re-run for a change inside it) and `glyph`; a node that sets one is `SUI-STATE-RUNTIME`. `_errors` is a content map with an English default per rule (`required`, `minLength`, `maxLength`, `min`, `max`, `pattern`) and a German overlay; one rule can be overridden with `_errors: { pattern: "Not a valid code" }`. The rules that set `error`, `touched`, `dirty` and the events and commands are E4.9 and E4.31.
- Tokens, group `field`: `label.gap` (`{space.gap.sm}`), `label.width` (`calc({size.control.lg} * 3)`, used when the title is on the left) `help.size` (`{text.caption.size}`), `selected.fill` and `selected.on` (the checked colours of the check, switch and radio controls) and `error.color` (`{color.danger.base}`). The control uses the `control` group of `control.css`. `density` re-declares the spacing tokens on the host, so the gaps and the control padding shrink with `compact`.
- Icon: `icon` is copied by the base controller to the runtime `glyph.name`, and the view draws `<ui-icon state=".glyph" size="{{ $.size }}">`; the icon is absent while `icon` is empty.
- The base, for the six other fields: `src/shared/css/field.css` (`@include "field.css";` after `control.css`) lays out the classes `field`, `label`, `box`, `icon`, `messages`, `help` and `alert` from the host attributes; `src/shared/field/field.ts` has `createField(context)` (keeps `glyph` and `message` in step, returns `widthOf` and `describedBy` for the view) and the pure `fieldWidth`, `fieldDescribedBy` and `fieldMessage`. A field's controller is `return createField(context)` plus whatever its control needs; its view repeats the small skeleton in `text-field.view.html` (the build has no HTML include) with its own control in `.box`.
- Validation (E4.9). Settings: `required`, `minLength` and `maxLength` (whole numbers, `0` means none), `min` and `max` (a number, or a string such as an ISO date; `""` means none) and `pattern`. `pattern` is a name from the closed list `email`, `url`, `integer`, `decimal`, `tel`, `alphanumeric` or a regular expression of at most 120 characters that must match the whole value; the shape validator `regex` of `@punyts/stateui-app` makes an expression that is too long, does not compile or has a nested quantifier such as `(a+)+` a `SUI-STATE-INVALID`. That guard is a first line only: it does not catch every slow pattern (`(a|aa)+`), so prefer the named patterns. Rules run in the order `required`, `minLength`, `maxLength`, `min`, `max`, `pattern`; `error` holds the first failing rule's name. An empty value fails only `required`. `min` and `max` compare numbers as numbers (a value that is not a number fails) and strings as text.
- Runtime articulation `error`, `touched` and `dirty` are `runtime: true`: a node that sets one, by value or link, is `SUI-STATE-RUNTIME`. `touched` is set on blur; `dirty` is true while `value` differs from the baseline, which is the value at mount (or what `reset` restored). `_errors` maps rule name to message (English defaults for all six rules, German overlay); a node overrides one with `_errors.required`; the `message` runtime property holds the text of the failing rule.
- Events and commands: `change` (`detail: { value }`, bubbles and is composed) is raised on every change of `value`, typed or written; the element's `commands` has `validate` (runs the rules, sets `error`) and `reset` (restores the baseline, clears `error`, `touched` and `dirty`). Once `touched`, a field validates itself on each `change`. The rest of the contract (E4.31): `invalid` (`detail: { rule }`) is raised on every failing validation and `valid` (`detail: { value }`) when a validation passes after one failed; the commands `focus` (the element with id `control` in the view) and `clear` (empties the value to `''`, `false` or `[]` by the baseline's kind, writes data and clears `error`); and on attach the host dispatches the bubbling, composed `ui-field-connect` event whose `detail` is a `FieldConnect`: `key` (the last path segment), `element`, `error`, `value`, `validate()`, `reset()`, `rebase()` (current value becomes the baseline, `dirty` false), `setManaged(mode)` (`none`, `blur`, `change`, `submit`; any mode but `none` stops the field validating itself on `change`, the form validates it), `setDisabled(flag)` (sets the runtime `locked`, which disables the control on top of `disabled`), `focus()` and `onRelease(callback)` (runs once when the field is removed, so a form drops it). With no listener nothing happens. The logic is `createField(context, valueName = 'value')` in `src/shared/field/field.ts` and the pure `failingRule(value, settings)`, `patternOf` and `NAMED_PATTERNS` in `src/shared/field/rules.ts`; a field with its value elsewhere (`checked`) passes `valueName`.
- Shared code in controllers: a controller is transpiled and never run by the build, and may not import a sibling file, but a relative import of a file `scripts/buildComponents.mjs` emits is fine. `buildComponents` transpiles every `.ts` under `src/shared/` (tests and `.d.ts` left out) to `shared/<folder>/<file>.js` beside `components/` (in `dist/` and in each test build), so a controller writes `import { createField } from '../shared/field/field.js'`. Unlike `../icons/core.js` this needs no per-file list, and the shared code is type-checked by `tsc` because it lives in `src/`.

## Fields: `checkField`, `switchField`
- Folders `components/molecules/check-field/` and `switch-field/`. ## Fields: `numberField`
- `numberField` (E8.30, folder `components/molecules/number-field/`): a field-family member on `createField` (the field contract, `titlePosition`, `width`, shared `size` and `density`, the `field` tokens). `value` is a number, or an empty string for none; `min`, `max`, `step`, `format` (`number` default, `percent`, `currency`), `currency` (an ISO 4217 code, required when `format` is `currency`), `stepper` (default true; reflected), `required`; the runtime `text` is what the input shows. Content `_label`, `_placeholder`, `_help`, `_decrement` (`Decrease`) and `_increment` (`Increase`) name the buttons, and `_errors` has `required`, `min`, `max`, `step` and `number`, each with a German text.
- Typing is read with `$.locale` by `parseNumberInput` (`src/shared/format/numberInput.ts`): `1.234,5` in `de`, `1,234.5` in `en`; a group separator must sit between groups of three digits (`1,23` is not a number in `en`), white space is ignored, a currency symbol or code and a percent sign may be left out, and the locale's own digits are read. `percent` stores a fraction and is typed as a percentage (`50` is `0.5`, shown `50 %` in `de`); `min`, `max` and `step` are in the stored unit. Every input event writes the parsed number to `value` (through a link, so `$.data` keeps a number); text that does not parse is kept as typed, writes nothing and sets `error` to `number` at once, before the field is touched. Clearing the text writes an empty string. On blur, and after a data write, a language switch or a step, the text is shown by `formatNumberInput` (up to 10 decimals, 8 for a percent, a currency's own digits); it is never rewritten while the user types.
- The input is `role="spinbutton"` (`aria-valuenow`, `aria-valuemin`, `aria-valuemax` and `aria-valuetext` from the value and the shown text). The minus and plus buttons (outside the tab order, named by `_decrement` and `_increment`) and ArrowDown and ArrowUp step by `step` (1 when it is 0), from 0 when the field is empty, clamped to `min` and `max`, and a step after an unparseable entry starts from the last written value. They do nothing while `disabled`, `locked` or `readonly`. The `step` rule fails a value that is not a whole number of steps from `min` (from 0 without one), with a tolerance for floating-point error; `min`, `max`, `required` and `step` are the base's rules, checked after the `number` entry rule.

## Fields: `sliderField`
- `sliderField` (E8.4, folder `components/molecules/slider-field/`): a field-family member on `createField` (the field contract, `titlePosition`, `width`, shared `size` and `density`, the `field` tokens). `value` is a number, or `[low, high]` when `range` is true (an empty string for none: the thumbs then sit at the start, a range at both ends, and nothing is written until the user acts). `min` (0), `max` (100), `step` (1; a step that is not above 0 counts as 1), `range`, `showValue` (default true; the `output` after the track), `format` (`number`, `percent` from a 0 to 1 value, `duration` from seconds), `marks` (a keyed map: the key is the value, `_label` is content, so a locale overlay translates it; a mark outside `min` to `max` is hidden), content `_label`, `_help`, `_low` and `_high` (`Minimum` and `Maximum`, the names of the two thumbs of a range) and `_errors` (`required`, `min`, `max`, `step`), each with a German text.
- Each thumb is a `role="slider"` span with `aria-valuemin`, `aria-valuemax`, `aria-valuenow` and `aria-valuetext` (the value formatted with `$.locale`); in a range the lower thumb's maximum is the upper thumb's value and the upper thumb's minimum is the lower thumb's. The arrows step (Left and Right swap in right-to-left text), Page Up and Page Down move ten steps, Home and End go to the limits, and the thumbs of a range cannot cross. Every value the slider writes is on a step counted from `min` and inside the limits; a value written from outside is shown clamped and never written back. The `min`, `max` and `step` rules of the field base judge each number of a pair.
- Dragging: a press on a thumb or on the track captures the pointer (a press on the track moves the nearer thumb there first); the pointer position becomes a value through the track width that a `ResizeObserver` reports, relative to where the press began, so no layout is read while dragging. `value` is written as the snapped number changes. The thumb and mark positions are the custom property `--sui-value` (0 to 100, from the runtime `lowPercent`, `highPercent`), and the filled part uses `--sui-from` and `--sui-to`, so the view only writes. Nothing moves while `disabled`, `locked` or `readonly`. Helpers are in `src/shared/slider/slider.ts`.

## Fields: `comboboxField`
- `comboboxField` (E8.31, folder `components/molecules/combobox-field/`): a field-family member on `createField` (the field contract, `titlePosition`, `width`, shared `size` and `density`, the `field` tokens, `icon`). `options` is a keyed map (`{ "open": { "_label": "Open" } }`: the key is the value and a locale overlay translates the label) or a data array read by `optionValue` and `optionLabel` (the value keeps its type); `allowCustom` (default false), `minChars` (0), `maxResults` (50). Content `_label`, `_placeholder`, `_help`, `_more` (`Keep typing to narrow the results`), `_empty` (`No matches`) and `_errors` (`required`), each with a German text.
- Typing filters the options by label with `Intl.Collator` for `$.locale` at base sensitivity (case and accents do not count: `e` finds `é`, and `u` finds `ü`), in option order. At most `maxResults` show; when more match, a last row asks the user to keep typing. Below `minChars` typed characters the list stays closed. The runtime properties `text` (the input's text), `open`, `results`, `hint` and `activeId` are what the view draws; they are not for authors.
- ARIA 1.2 combobox: the input has `role="combobox"`, `aria-expanded`, `aria-controls` and `aria-activedescendant` (focus stays in the input); the list is a `listbox` popup (the popover API, anchored to the input) whose options carry `aria-selected` for the chosen value. ArrowDown opens with the chosen option active (ArrowUp with the last), the arrows move and wrap, Enter chooses the active option, Escape closes and restores the text of the value; a press on an option chooses it and keeps focus in the input. While typing, the first match is active unless `allowCustom` is on; with `allowCustom`, Enter takes the typed text unless an option was made active.
- Leaving the field: text that is exactly an option's label chooses that option; other text becomes the value (trimmed) with `allowCustom`, and otherwise the last value and its label come back; empty text clears the value. The label of the chosen value stays shown when `options` no longer holds it. The list behaviour is `createCombo` in `src/shared/field/combo.ts`.
- Server-side search (E8.32): the field raises `query` (`detail`: the typed text; wire it with `on.query` to an `emit`) after the user typed, once `minChars` characters are in and 300 ms passed without more typing (empty text counts when `minChars` is 0; a value written from outside, a choice, and leaving the field before the pause do not raise it). The runtime `busy` is the controller's alone: it sets `busy` as it raises `query` and clears it on the next write to `options`, or after 5 seconds when none comes (an application-owned source ignores `query`, so nothing spins forever). While `busy` the list shows a spinner row with the content `_loading` (`Searching`; German `Suche läuft`) and no "no matches" row. A write to `options` while the list is open redraws it once, in place, and keeps the active option when its value is still listed (else the first match, or none with `allowCustom`). The chosen label stays in the input after `options` is replaced by results that no longer hold it.

## Fields: `multiSelectField`
- `multiSelectField` (E8.3, folder `components/molecules/multi-select-field/`): a field-family member on `createField` whose `value` is a list (an array; written through a link as an array). It has the `comboboxField` options (`options`, `optionValue`, `optionLabel`, `minChars`, `maxResults`, `allowCustom`, the `query` event, `busy`) and the same input and list (`createCombo`, `src/shared/field/combo.ts`), plus `minSelected` and `maxSelected` (0 means no bound). Content `_label`, `_placeholder`, `_help`, `_remove` (`Remove {label}`; German `{label} entfernen`), `_more`, `_loading`, `_empty` and `_errors` (`required`, `minSelected`, `maxSelected`), each with a German text.
- Chosen values are chips inside the control (the runtime `chips`), each with a remove button named by `_remove` with the label in place of `{label}`. The label of a value comes from `options`, else from the last time it was seen there, else the value itself, so a chip keeps its label when `options` is replaced by search results. The list is a multiselectable `listbox`: it stays open while options are picked, a chosen option has `aria-selected`, and pressing it again removes it. Backspace in an empty input removes the last chip. `change` carries a copy of the list.
- Tag mode (`allowCustom`): Enter or a comma adds the typed text, trimmed, as a value (text that is the label of an option adds that option); pasted text is split at commas and the last piece stays in the input. A value that is already in the list is never added twice (the comparison is exact, so `KIWI` and `kiwi` differ); the typed text is then dropped. Without `allowCustom`, text that is not an option's label stays in the input. Leaving the field drops text that was not added. `maxSelected` stops adding by any means.
- Rules (`src/shared/field/rules.ts`, `FIELD_RULES`): `minSelected` and `maxSelected` compare the number of values; like the other rules, an empty list fails only `required`. `createField` now raises `change` once per change of the value (a list write used to raise it once per entry), with a copy of a list value.

## Loading: `skeleton`, and `loading` on `card` and `stat`
- `skeleton`: `shape` (`text`, `rect`, `circle`; reflected), `lines` (default 1, 1 to 20, `text` only), `width` (`fill` or a `ch` or `%` value, such as `12ch` or `50%`; anything else is `SUI-STATE-INVALID`) and `ratio` (`1:1`, `4:3`, `16:9`; `rect` only). `text` draws `lines` bars one body line high, the last one 60 percent of `width` when there are several; `rect` is a block with the `ratio`; `circle` is a square with a full radius, and its `fill` width is the medium control height. Component token `radius` (`{radius.sm}`, group `skeleton`) rounds `text` and `rect`. The whole thing is `aria-hidden`. - `loading` (boolean, reflected) on `card` and `stat`: the title and subtitle (card, with the body) or the value (stat) are replaced by `<ui-skeleton>` and the host has `aria-busy="true"`, removed when `loading` is false. The card keeps its media, actions and footer, and its `press` behaviour; its children stay mounted but hidden, so turning `loading` off does not rebuild them. Both components need `skeleton` in the library. Record views, `list` and `table` get `loading` in E5.24.

## Tips: `tooltip`, and the icon-only `button`
- `tooltip` (E4.18): `side` (`top` by default, `bottom`, `start`, `end`; reflected; it is not called `placement` because the tree owns that name), `delay` (ms, 500), content `_text` and the slot `trigger` (a node). Tokens, group `tooltip`: `padding` (`{space.inset.sm}`), `radius` (`{radius.sm}`) and `maxsize` (`calc({size.control.md} * 8)`). It shows after `delay` on pointer hover (a touch pointer never starts it) and at once when the trigger takes focus, and hides on Escape, blur, pointer leave and a press outside. It holds text only and is `aria-hidden`.
- Anchor and description (decided by spike E4.32): the popover stays in the tooltip's shadow root and the shadow stylesheet gives the trigger wrapper `anchor-name: --t` (a name set from the light DOM does not anchor a popover in a shadow root; because `trigger` is a node slot drawn with `<sui-node>` inside the shadow root, the wrapper is not a `::slotted()` element, but the rule is still the shadow stylesheet's). The trigger is described with `aria-description`, set on its first focusable element, looking through shadow roots (the native button of a `button` component), and removed when `_text` is empty; `aria-describedby` cannot reach the popover and `ariaDescribedByElements` does not cross the boundary. The tests read the description from the accessibility tree (CDP `Accessibility.getFullAXTree`).
- Icon-only `button`: with `iconPosition: "only"` the button shows its `_title` through the same code, with no `tooltip` node (its own `aria-label` already names it, so it gets no description).
- Shared code, `src/shared/popover/`: `popover.ts` has `createPopover({ element, placement?, anchor?, inside?, onDismiss? })` returning `open`, `close`, `isOpen`, `setPlacement`, `setAnchor` and `dispose`. The element becomes a `popover="manual"`, the placement is written as `position-area` (`start` and `end` as `inline-start` and `inline-end`) and the anchor name as `position-anchor`, and while open it closes on Escape and on a press outside itself and the `inside` list. It reads no layout and needs no component (the chart tooltip of E8.12 uses it directly); it is exported from the package. `tip.ts` (`attachTip`: hover delay, focus, leave, blur) and `tipMixin.ts` (the `tip` and `tip-describes` directives, registered by a controller with `registerTipMixins()`) are for `menu`, `popover` and the other users inside the library.
- Minimum browser: anchor positioning in a shadow tree and `aria-description` were measured in Chromium 149 (the Playwright 1.61 Chromium the browser tests run in) and nothing older was tried, so 149 is the minimum Chromium the library supports for `tooltip`; the CSS also uses `position-area`, `position-try-fallbacks`, `@starting-style` and `transition-behavior` through `allow-discrete`.

## Composites: `page`, `nav`, `menu`
- `page` (E5.2): `navPosition` (`start` beside the main area, `top` above it, `none` removes the nav from the layout; reflected), `maxWidth` (`none`, `md` 768, `lg` 1024, `xl` 1280 px, limits the main area, reflected), `navBreakpoint` (integer px, default 768; 0 never collapses), `navOpen` (default false, reflected; articulation property: write it to open or close the collapsed nav), runtime `compact` (reflected; true while `navPosition` is `start`, a `nav` is set and the page element is narrower than `navBreakpoint`), content `_title` and `_navLabel` (the menu button's text, `Menu`, German `Menü`), slots `header`, `nav`, `footer` and `children` (the main area, with `layout`); tokens, group `page`: `padding` and `gap`. ## Composites: `form`
- `form` (E5.3, folder `components/composites/form/`): shared `density`; `validateOn` (`blur` default, `change`, `submit`), `disabled`, slots `children` (with `layout`) and `actions`, content `_errorSummary` (German overlay). Two fields with one key are reported through `report.error` as `SUI-RUN-BINDING` (the catalog has no duplicate-key code) and the later field in document order wins. `reset` calls every field's `reset()` (the baseline is written through the field's link, so `$.data` returns to it), clears the validation state and raises no `changed`; `commit` calls every field's `rebase()`, making the current values the new baseline. The form saves nothing: `$.data` already holds typed values, and `submitted` only reports them; a host acts on it with `on` (`emit` reaches `hooks.onEmit`, `set` writes a flag). `status` is now `pristine`, `dirty`, `invalid`, `submitting` or `submitted`.
- Fields with work under way (G2.9): `FieldConnect` has `settle()`, which brings the field's work under way to an end and returns a promise that resolves when it has ended (whatever the outcome), or undefined when there is none; a field supplies it with the `settle` option of `createField`, and `createWaiters()` in `src/shared/field/field.ts` hands out and wakes its promises. `fileField` answers it while transfers are under way, `paintField` saves a dirty painting at once. `submit` asks every field; when any answers with a promise the form stays `submitting`, waits, asks again (a field may start new work, at most 20 rounds) and only then validates and collects the values, so the values are those after the work and a failed transfer or save refuses the submit. A second `submit` while one waits does nothing, and a `reset` or dispose drops the waiting submit. With no work under way a submit runs at once as before. `submitted` copies each list and plain object value.

## Records: `recordList` (slot pool)
- `recordList` (E5.20 and E5.23, folder `components/composites/record-list/`): draws only the visible records of an array or keyed map through a small pool of recycled row nodes. Shared `density`; `key` (the field of an array record that holds its key, default `id`; a keyed map is keyed by its own keys), `rowHeight` (`sm`, `md`, `lg`, `xl`; reflected: `md` is the `recordlist.row` token, `sm` and `lg` the small and large control heights times the density factor, `xl` 1.5 times the large height, for two-line rows; any other height: keep `md` and override the token on the node, `"theme": { "recordlist": { "row": "72px" } }`, which `list` and `tree` pass down to their body because custom properties inherit; the token has no effect while `rowHeight` is `sm`, `lg` or `xl`), `overscan` (0 to 20, default 5), data `records` (array or keyed map) and `order` (array of keys), `selected`, `loading`, `total` (accepted, no behaviour yet), slots `row` (the template, a `row: true` node) and `empty`, runtime `count` (the number of positions) and `slots`. Tokens, group `recordlist`: `row` (default `calc({size.control.md} * {density.factor})`, the row height `--sui-row-h`).
- The slots are nodes at `runtimePath(nodePath).slots.<i>`, aliased at `$.<node>.slots` for the view. The window `{ first, count }` is read from `runtimePath(nodePath).window` (written by the observer, or by a test); with no window it is `{ 0, 0 }`, so the pool has `2 * overscan` slots. N = `count` + 2 x `overscan`, at most 200 (the cap takes from the overscan first). Position `p` shows in slot `p % N`, so a window move recycles only the slots whose position changed.
- A recycled slot costs one `store.link` (`slots.<i>.row`, re-pointed at the record) and one write of `slots.<i>.slotIndex`, which the view binds to `--sui-index`. The template's `$row.x` links are rewritten once per slot by `resolveRowLinks` to fixed `allowMissing` aliases under `slots.<i>.row.x`. A position with no record points `row` at `$.runtime.empty` and the slot is `hidden`. Records need a key: an array record without one shows as an empty slot. Links in the template that are not `$row` links are not copied to the slots.
- An array keeps a key-to-index map from the store events (insert, update, delete, `length`, replace), so a window move never scans the array; `store.delete` of an array element moves the followers without an event, so the slots are pointed again. `order` entries that name no record are skipped.
- A change to the `row` template rebuilds the pool; one that changes only `_` content (a language switch) is written into the existing slots. Refreshes from the window, the data and the template are coalesced into one per microtask, so a test awaits one turn after a write. The pool starts in the first microtask after mount (the controller runs while the node renders, and replacing the default of `slots` there would re-render the node).
- Positioning, observer and accessibility (E5.23): the host is the scroll container's parent and `.list` scrolls (`overflow-y: auto`, `scrollbar-gutter: stable`); the scroll content is `calc(var(--sui-count) * var(--sui-row-h))` and each slot is `translateY(calc(var(--sui-index) * var(--sui-row-h)))`, with `--sui-row-h` the `recordlist.row` token. Size the host (a height) so the list has a viewport. `createViewportObserver` (`src/shared/records/viewport.ts`, for `recordGrid` too) is the only layout read: one passive scroll listener reads `scrollTop` once per animation frame, and a `ResizeObserver` on the scroller and on a hidden probe of `--sui-row-h` height gives the viewport and row heights, so a token write or a `density` change re-flows the rows; it writes `window` only when `first` or `count` changes. The event `range` (`{ first, count, total }`, `total` the record count) is raised once per change of `window`, and the window is copied to the articulation property `window` (passed up by `list` and `table`), where app logic watches it and fills the records with `query`; writing it does not scroll. `role` (`list` default, `listbox`, `table`, `rowgroup`; reflected) gives the host role and the slot role (`listitem`, `option`, `row`, `row`); `list` and `listbox` slots carry `aria-setsize` and `aria-posinset`, `table` and `rowgroup` slots `aria-rowindex` (1-based plus `rowIndexOffset`, default 0, for rows above the body such as a header), and a `table` host `aria-rowcount` (the reflected `ariaRowcount`, written by the controller from `count`). Each slot draws `box-shadow: var(--sui-row-divider, none)`, the hook a component built on the record view sets for a row divider.
- Selection, focus, `locate`, `scrollTo`, `loading` (E5.24): `selected` (a key, a number or a list of keys; a link such as `"<-selected": "$.data.picked"` works) is shown on each slot of a selected record as `data-selected`, and as `aria-selected` for the role `listbox`, so recycling cannot move it. The slot nodes carry the runtime properties `slotIndex`, `slotSelected` and `slotTab`. Exactly one visible slot has `tabindex="0"`: the slot of the last focused record, else the first visible position. Arrows, Home, End, PageUp and PageDown (a page is the visible rows less one) move the focus by position: the observer scrolls the target in with `reveal` (a write of `scrollTop` and of `window`), the pool refreshes, then the slot that shows it is focused. Keys typed in an input, textarea or select of a row are left alone. A focused slot is pinned by key (`pin` in `createSlotPool`): while its record is out of the window the slot is left out of the recycling and the others cover one position fewer, so the element keeps focus and returns to the ring when the record is back; if the record moves in the window focus follows it; if it is deleted the pin is released and focus goes to the row now at that position (the last row if it was last). The element has `locate(key)` (the path of the record through the `records` alias, `$.app.<node>.records.<i>`, or the shared empty record `$.runtime.empty`, read from the key index, no scan) and the command `scrollTo` (a key; writes `scrollTop` through the observer and the window follows; an unknown key throws, which the runtime reports as `SUI-RUN-ON-COMMAND`). `RecordViewElement` (`src/shared/records/recordView.ts`) types both for `list` and `table`. `loading` (boolean, reflected) sets `aria-busy` on the host and shows `<ui-skeleton>` rows (`.placeholder`) over the visible rows, whether or not records exist, and hides the real rows (`visibility: hidden`) without rebuilding them. Row `on`: a `$row` target or value works from a button in a row (tested); the slot renders through its alias in `$.app` and the `on` dispatcher maps that path to the runtime slot (stateui-app).
- For a component built on it (E5.8): `multiselectable` (boolean, default `false`) sets `aria-multiselectable` (`true` or `false`) on a `listbox` host; the element also has `keyAt(position)` and `recordKeys()` (the keys of every position in order); a selected slot draws `background: var(--sui-row-selected, none)` and every slot `cursor: var(--sui-row-cursor, auto)`.
- The code is in `src/shared/records/` (`createRecordIndex`, `createSlotPool`, `poolSize`, `poolStart`, `readWindow`), for `recordGrid` to reuse. The observer, ARIA, selection and keyboard are E5.23 and E5.24; the view already positions slots with `--sui-index` and `--sui-row-h`.

## Records: `tree` (flattening and rendering)
- `tree` (E8.8, folder `components/composites/tree/`): hierarchical records drawn through a `recordList` body, like `list`. Shared `density`; `key` (default `id`), `parentField` (default `parentId`: the record field that holds the key of the parent; empty, or a key that no record has, makes a root), `childrenField` (default empty; when set, the field holds a list of the keys of the children, in display order, and replaces `parentField`; the records stay flat), `hasChildrenField` (default `hasChildren`), `labelField` (default `label`), `expanded` (a list of keys whose children are shown), `indent` (`sm`, `md` default, `lg`: the `space.inset` step of `--sui-indent`; reflected), `rowHeight` (`sm`, `md` default, `lg`, `xl`; passed to the body), data `records` (an array keyed by `key`, or a keyed map) and the slot `row` (a row template, where `$row` is legal).

- There is no `$level` local. The depth is also the custom property `--sui-level` on the slot, for a row template that wants it.

## Records: `tree` (keyboard, selection and lazy children)
- `tree` (E8.9): the body has the role `tree`, and each slot is a `treeitem` with `aria-level` (from 1), `aria-expanded` (`true` or `false`; absent for a record with no children), `aria-setsize`, `aria-posinset` (among its siblings) and an `aria-label` from `labelField`. The pool gets these from the tree through the record view's `slotMeta` hook; a busy row is `aria-hidden`.
- Keys, on a focused row: Down and Up move to the next and previous shown record, Home and End to the first and last, Right opens a closed record or moves to its first child, Left closes an open record or moves to its parent (Left and Right swap in right-to-left text), a character jumps to the next shown record, wrapping round, whose `labelField` starts with it (case-insensitive), Space picks the record, Enter raises `activate`. The record view's own arrow keys are off for this role, so the tree owns them. A press on a record that can open opens or closes it (a double press raises `activate` and opens or closes once).
- Selection is the shared selection code: `selectable` (`none` default, `single`, `multi`; reflected), data `selected` (a key, or a list of keys in `multi` mode; aliased as the body's `selected`), the events `select` (the keys) and `activate` (the key); the body gets `aria-multiselectable` in `multi` mode and each slot `aria-selected` while the tree is selectable.
- Commands: `expand` and `collapse` (`value`: a record key; a key that is unknown, or a record with no children, is ignored), `expandAll` (every record that has children loaded) and `collapseAll`. All of them, a key, a press and a write to `expanded` go through `expanded`.
- Lazy children: a record is marked as having children when its `hasChildrenField` value is true. ## Charts: the scale module
- `src/shared/chart/scale.ts` (E8.11) holds what every chart type draws with, as pure functions with no DOM: `createLinearScale(domain, range)` and `createBandScale(categories, range, { padding, outerPadding })` (both with `invert`; a band scale inverts to the category whose band is nearest, and to nothing outside the range), `niceTicks(min, max, count, format?)`, `stack(series)`, `extentOf` and `stackExtent`.
- `niceTicks` returns the tick `values`, their `labels`, the `step` and the rounded `min` and `max` the axis covers. The step is 1, 2 or 5 times a power of ten and binary noise is rounded away (`0.1 * 3` gives `0.3`); a range with no span covers 0 to the value (0 to 0 covers 0 to 1). The module has no locale code: labels come from the `format` callback the caller gives (a chart passes `formatValue` for `$.locale`), and are `String` without one.
- `stack` stacks positive values upwards and negative values downwards from 0 in series order, so a negative value never sits on a positive one; a value that is not a finite number counts as 0.
- `src/shared/chart/drawingTree.ts` (G2.1 of the graphics epic 2, not exported from the package) turns a chart scene (`buildScene`) into the shape tree of the drawing model: `sceneToTree(scene, { path? })` gives `shapes` (a `drawGroup` per layer `grid`, `axes`, `marks`, class `layer <name>`; each primitive as `line` with two `points`, `drawText`, `rect`, `path` or `circle`, its geometry as properties, its path `<layer>.<id>` stable between calls) and `data` (the `Point` of each mark, keyed by the shape's path). The `s1`..`s8` class becomes the paint `{color.data.categorical.N}`: bars and slices fill, lines stroke (fill `transparent`, width 2, round caps and joins), areas fill at `opacity` 0.2 with no stroke, points and slices have a `{color.surface.base}` stroke. The rest of the class is kept in `attrs.class`, `data-*`, `role`, `aria-label` and `tabindex` in `attrs`, and a text's `dy` becomes its `baseline` (`0.32em` `middle`, `1em` `hanging`). Gridlines, the baseline, ticks and the donut total also get their stylesheet paint and text anchor, for a renderer without the stylesheet. The chart draws through it since G2.2.

- `legend` (`bottom` default, `end`, `none`; reflected) lists the series, and for a donut the slices, as buttons with `aria-pressed`. Pressing one adds its key to `hiddenSeries` or takes it out (an array on the node, so the application or a minion can write it too; a donut uses the slice label as the key) and the chart draws without it: the other series keep their colour and the value axis fits what is shown. The legend list is labelled by `_legend`.
- Every bar, point and slice is a mark with `role="img"`, an accessible name (`Revenue, Feb: 2,000`; a slice: `Rent: 30 (30%)`), `data-point` (its id) and a roving `tabindex`: one mark is the tab stop. Left and Right move between categories of the series, Up and Down between series at the category, Home and End to the ends (Left and Right swap in right-to-left text; all four arrows step round the slices of a donut).
- Hovering or focusing a mark opens a tooltip with the category (or slice label) and the value of every shown series, the series of the mark in bold (a slice: its value and its share, `_share`). It is drawn with `createPopover` (E4.18) on an element `.tip` in the plot and anchored to a zero-size element `.anchor`, which the controller places with the custom properties `--sui-ax` and `--sui-ay` from the point the scene computed, because an SVG mark cannot be a CSS anchor and nothing reads layout. Escape, blur and pointer leave close it, and it follows a redraw while open.
- A visually hidden `table` (`.data`, built with `createElement`) holds the same values: the caption is `_title`, the header row is `_category` and the series labels (a donut: `_category`, `_value`, `_share`) and each record is a row with a row header. It keeps hidden series and slices, because it is the data, and a data change rewrites only the cells that changed. The `de` overlay translates `_title`, `_legend`, `_total`, `_category`, `_value` and `_share`; series labels come from `series.<key>._label` overlays.
- Finding: the template parser makes every element HTML, so an `svg` written in a view is an `HTMLUnknownElement` that draws nothing. The controller creates the `svg` with `createElementNS` and adds it to the plot, and attaches its pointer, focus and key handlers itself.
- `interactive` (boolean, default false; reflected, G2.4 of the graphics epic 2) makes the marks pressable: a click on a bar, line point or slice, or Enter or Space while it has focus, raises the event `press` (declared in `events`) with `detail: { key, series }`, the key of the mark's record and the series key (a slice: its record and the first series). The record key is an array's index as a string or a keyed map's key, in the order the chart draws them (`readKeys` in `src/shared/chart/data.ts`, beside `readRows`). An `on.press` entry gets the detail as its payload (an `emit` without a value hands it to the host). The chart raises it itself, not through `interactive` shapes of the renderer, so the marks keep `role="img"`, their names and the single tab stop, and the `svg` keeps `role="group"` and its labels; the marks show a pointer cursor. A hidden series draws no marks, so it has nothing to press. Without `interactive` nothing is raised and the drawing is the same.

Content `_limitExceeded` (the hidden text of a header past its limit). Tokens, group `board`: `card` (`calc({size.control.md} * 2)`), `column` (the column width) and `height` (the height of a column body).

- A column is made once and kept: its body is stored with `ready: false`, its aliases are linked and only then `ready` is written, so the record view finds its data when it starts, also for a column added after the board is drawn. A key that leaves `columns` hides its column (`data-gone`: out of the flow, still at its size so the viewport that the record view measures does not collapse, with an empty order) and shows it again when the key returns. Columns are drawn in the order of `columns` (a CSS `order` from `cols.<name>.position`). Taking a column out of the store was not done: a record view that is removed, or that collapses to no height, destroys its slot nodes before the view has let go of them, which is reported as `SUI-NODE-MISSING`.
- The header shows the title and a `badge` node (runtime `cols.<name>.badge.main`, drawn with `<sui-node>`) with the number of cards and `/ limit` when there is one. Past the limit the badge is `tone: "warning"` with `variant: "solid"`, the header has `data-tone="warning"` and the hidden text `_limitExceeded` is added for screen readers (the board has no `tone` property of its own, because that name is the shared articulation, and its stylesheet names no tone colour: the badge brings them). A record whose value matches no column is not shown and the controller reports it once per distinct value through `@punyts/core` as `SUI-RUN-BINDING` (a warning), because the data is not known to the static validator; a value that goes away and returns is reported again. The `de` overlay translates `_limitExceeded`, and column titles come from `columns.<key>._title` overlays.

## Composites: `board` (drag, keyboard move and `move`)
- `board` (E8.14) implements the decision below. New: the event `move` (`detail`: `{ key, from, to, index }`), `labelField` (default `title`: the record field that names a card in announcements; the key when it is empty) and the content map `_moveAnnouncements` (`pickedUp`, `moved`, `dropped`, `cancelled`, with `{name}`, `{position}`, `{count}` and `{column}`; `de` overlay).
- Pointer: after 4 pixels of movement a press on a card (not on a button, link or field inside it) becomes a drag. The board captures the pointer, dims the card (`opacity` on its slot), sets `data-dragging` on its root and shows a dashed placeholder box of one card height (`cols.<name>.drop` and `dropScroll`, drawn by the view with `--sui-drop-index`) at `floor((pointerY - top + scroll) / cardHeight)` in the column under the pointer. The column boxes and body scroll are read once at drag start, and the card height comes from a `ResizeObserver` on a probe element, so moving the pointer reads no layout (a test spies on `getBoundingClientRect`). Releasing writes the card (see the order rules below) and raises `move`; releasing on the card's own place, Escape and `pointercancel` write nothing.
- Keyboard: Space on the focused card picks it up (the placeholder shows where it is), Up and Down move it inside the column, Left and Right to the neighbouring column, Space drops it and Escape cancels; the focus stays on the card, and follows it after the drop. The board listens for keys in the capture phase, so while a card is picked up the record view's own arrow keys do not move the focus. Losing the focus cancels. One polite live region (`role="status"`) announces every step.
- Writes go through the record path found with the column body's `locate(key)`: `columnField` (when the column changes) and `orderField` (a number between the new neighbours, or the whole column numbered from 1 when that is not possible; without an `orderField` a move inside a column does nothing and no placeholder shows there). The pure planning is `planMove` in `src/shared/records/board.ts`; the geometry and keys are `src/shared/drag/drag.ts`. `move.index` is the index the card has in the target column after the writes.

## Decision: drag and drop (E8.14, `board`)
Drag and drop is a new class of interaction for the library, so the model is recorded here before any code. It applies to `board` and to any later component that moves a record between positions; the pure part is `src/shared/drag/drag.ts`.

- **A move is a data write.** The data is the board: a drop writes the record's `columnField` (when the column changes) and `orderField` (when the board has one) at the path of the record, found with the column body's `locate(key)`, and then raises `move` with `{ key, from, to, index }`. `from` and `to` are column keys and `index` is the place the card has in the target column after the writes (from 0). Nothing is moved in the DOM: the orders of E8.13 follow the data and the slots are recycled as before. The same code commits a pointer drop and a keyboard drop.
- **Order values.** The moved record gets an `orderField` number between its new neighbours (their average, one past the last, one below the first, 1 in an empty column). When that is not possible (a neighbour has no number, equal numbers, no room left) the whole target column is numbered from 1 in the new order, which writes the other records too. Without an `orderField` a card cannot be put at a place inside a column: a move between columns writes only `columnField` and the card ends where the record order puts it (`move.index` says where), and a move inside a column does nothing.
- **Pointer.** A press on a card (not on a button, link or field inside it) starts nothing yet; after 4 pixels of movement it becomes a drag and the board captures the pointer, so the card never receives the click. The column under the pointer is chosen by its horizontal position (the nearest one outside them all) and the place is the index of the card the pointer is over, `floor((pointerY - top + scroll) / cardHeight)`, clamped to the list (one past the last card for another column). The card height is the `--sui-card-h` size reported by a `ResizeObserver` on a probe element, and the column boxes and the scroll of the column bodies are read once, when the drag starts: pointer moves read no layout and no card. A placeholder (a dashed box of one card height at that index, `cols.<name>.drop`) shows where the card will land, the dragged card is dimmed, and the page is not scrolled by the drag (a long column is scrolled before the drag starts). Releasing outside every column, or at the place the card came from, moves nothing; Escape or `pointercancel` cancels.
- **Keyboard.** The focused card is picked up with Space. Up and Down then move it one place inside its column, Left and Right to the previous and next column (swapped in right-to-left text) keeping the index as far as the list reaches, Space drops it and Escape cancels, which puts nothing back because nothing was written until the drop. Focus stays on the card and follows it after the drop. While a card is picked up the arrow keys and Space are the board's, not the record view's.
- **Announcements.** One polite live region (`role="status"`, `aria-live="polite"`, `aria-atomic`) says what happened at each step: `pickedUp`, `moved`, `dropped` and `cancelled`, from the content map `_moveAnnouncements` (English default, `de` overlay) with the fields `{name}` (the card's `labelField`, default `title`, or its key), `{position}` (from 1), `{count}` (the cards in the target column after the move) and `{column}` (the column title). A pointer drop announces `dropped` too.
- **Left out on purpose:** autoscroll while dragging, dragging several cards, touch long-press and a drag image (the placeholder and the dimmed card stand in for it).

## Dates: the `dates` module (E8.15)
- `src/shared/dates/` is the shared date code of `calendar` and `dateRangeField`. It has no date library dependency and never uses the `Date` of the machine for calendar arithmetic: a day is a number of days since 1970-01-01 (`dayNumber`), so a daylight saving change cannot repeat or skip a day. Dates in state are ISO strings: `YYYY-MM-DD`, and `YYYY-MM-DDTHH:mm` (seconds and a fraction are allowed) for a time. A time without a zone is the wall-clock time it shows; a time with a zone (`Z`, `+02:00`) is shown at the viewer's local wall-clock time.
- Where each thing is read (the decision of design Open Question 7, recorded in `knowledge-base/design/stateui-ui-builder.md`, Locale): the **first day of the week** from `Intl.Locale.prototype.getWeekInfo()`; **month and weekday names** from `Intl.DateTimeFormat` for `$.locale` (UTC and the Gregorian calendar); **date formats** from `Intl.DateTimeFormat.formatToParts` for `$.locale` (a numeric day, month and year in the locale's order, such as `03/14/2026` for `en` and `14.03.2026` for `de`). A locale overlay never carries any of them; an unusable locale tag is read as `en`.
- Minimum browser: `getWeekInfo()` needs Chromium 130 (Chrome and Edge 130, Firefox 133, Safari 17). A browser without it uses `FIRST_DAY_BY_REGION`, the CLDR first day of the week by region (the region of the tag, or the region its language most likely has: `de` is `DE`, `ar` is `EG`); a region that is not in the table starts on Monday. The rest of the module needs only `Intl.DateTimeFormat` with `formatRange` (Chromium 76).
- `monthGrid(year, month, firstDay)` gives 42 days (6 rows of 7) from the week that holds the 1st, with `inMonth` for the days of the month. `parseDate(text, locale)` reads an ISO date or three numbers in the order of the locale (`4.3.2026` for `de`, and the digits of the locale's own numbering), needs a four-digit year and an existing day, and gives the ISO date or `undefined`. The package exports `monthGrid`, `addDays`, `addMonths`, `parseIsoDate`, `parseMoment`, `firstDayOf`, `weekdayNames`, `monthNames`, `formatDate`, `parseDate` and the other formatters (see `src/shared/README.md`).

## Composites: `calendar` (month view)
- `calendar` (E8.16, folder `components/composites/calendar/`): `view` (`month`, `week`, `day`; reflected), `date` (the focused date, an ISO date; empty means today until the user moves it), `startField` (default `start`), `endField` (default `end`; empty means every record lasts as long as its start), `titleField` (default `title`), `key` (default `id`), data `records` (an array keyed by `key`, or a keyed map); events `select` (an ISO date), `open` (a record key) and `range` (`{ start, end }`); content `_previous`, `_next`, `_today`, `_more` (`+{count}`) and `_moreLabel` (`More records: {count}`) with a `de` overlay. Tokens, group `calendar`: `cell` (minimum day height), `radius`, `selected.fill` and `selected.on` (today's number). Runtime properties the view draws: `heading`, `weekdays`, `weeks`, `visible`.
- Everything is computed by the controller from `src/shared/dates/` (`buildMonth` in `calendarModel.ts`) and written as state; the view only draws it and nothing reads layout. The grid is `role="grid"` of `role="row"` and `role="gridcell"`, six rows of seven days from the week that holds the 1st, with the first day of the week, the month heading, the weekday names and each day's name (`Saturday, March 14, 2026`) from `$.locale`. Days of the neighbouring months are shown muted (`data-outside`) and carry their records too.

- Keyboard: the grid has one tab stop, the cell of the focused date, and the records and `+n` button of that cell share it (the other cells' buttons are `tabindex="-1"`, still pressable). Left and Right move a day (swapped in right-to-left text), Up and Down a week, Home and End to the first and last day of the week, Page Up and Page Down a month, Shift with them a year (the day of the month is kept as far as the new month reaches), Enter and Space raise `select`. Every move writes `date` and the focus follows into the new cell. A press on a day writes `date` and raises `select`; a press on a record raises `open` and not `select`. The previous and next buttons and `Today` write `date` too.
- `range` is the first and last day of the visible grid (so it includes the neighbouring months' days; `{ start: "2026-03-01", end: "2026-04-11" }` for March 2026 with Sunday weeks). It is raised once whenever the visible range differs from the one drawn last, whatever changed it, and not at load; several writes to `date` before the next draw give one event. `visible` always holds the current range, so a data provider can read it at the start.

## Composites: `calendar` (week and day views)

New runtime properties: `days`, `hours` and `dayCount`; the month's `weeks` and `weekdays` are emptied while a time view shows, and the other way round.

## Fields: `dateRangeField`
- `dateRangeField` (E8.18, folder `components/molecules/date-range-field/`) is a field family member on `createField` (the field contract: `change`, `invalid`, `valid`, `validate`, `reset`, `focus`, `clear`, `ui-field-connect`, `error`, `touched`, `dirty`, `required`, `titlePosition`, `width`, shared `size` and `density`). Data `value` is `{ start, end }`, two ISO dates, each empty when not set (a `<-value` link to `$.data.range` works like any field's); `min` and `max` are ISO dates; `minDays` and `maxDays` are counts (0 means none). Content: `_label`, `_help`, `_start`, `_end`, `_open`, `_previous`, `_next`, `_pickStart`, `_pickEnd` and the `_errors` map (`required`, `format`, `order`, `min`, `max`, `minDays`, `maxDays`; `order` is a typed end before the start, which is kept as typed rather than swapped), all with a `de` overlay. `change` carries `{ value: { start, end } }`. Runtime properties: `startText`, `endText`, `open`, `picking`, `months`.
- Typing: two inputs show the dates in the form `$.locale` writes (`03/14/2026`, `14.03.2026`). A date that parses (the order of the locale, any digits and separators, a four-digit year, an existing day; an ISO date too) is written to that side of `value` at once, empty text empties the side, and text that does not parse stays as typed, writes nothing and fails the field's own rule `format`. Committing an input (Enter, or leaving it) puts the two dates in order (a start after the end swaps them) and shows them in the locale's form. The inputs are not rewritten while the user types a date that already means what `value` says.
- Popup: the button, or the Down arrow in an input, opens a popup in the top layer (the shared popover code, anchored to the field) with two months side by side from the month of the start (6 × 7 days each; the days of the neighbouring months are blank, so no date shows twice). The first press on a day makes it the start and waits (`picking`, shown in a live status line; nothing is written yet), the second makes it the end, writes the whole range, closes the popup and returns the focus to the start input. A second press before the first swaps them, the same day twice is a one day range, and the days from the start to the end are highlighted (`data-in-range`, `data-edge`, `aria-selected`). Days outside `min` and `max` are shown and `aria-disabled`, and cannot be picked. The keyboard is on one day, the one tab stop: arrow keys, Home and End, Page Up and Page Down (a year with Shift) move it and bring other months into view when it leaves the two shown; Enter and Space press it; Escape closes the popup and returns the focus to the input; a press outside, or the focus leaving the field, closes it. The previous and next buttons move both months.
- Rules, in this order (`exclusive`: the shared rules do not run, because the value is an object): `format`, `required` (both dates), `min` and `max` (either date outside), `minDays` and `maxDays` (the number of days in the range counting both ends, so 1 March to 3 March is 3 days; an incomplete range is not judged). The field is touched when the focus leaves the field, not when it moves between its inputs and button. Logic: `src/shared/dates/range.ts` (`failingRangeRule`, `pickDay`, `markDay`) and `picker.ts` (`buildPicker`).
- The field base gained three things for a value that is an object: `exclusive` (the `entryRule` is the only rule), `empty` (what `clear` writes), and a copy of the baseline (`reset` restored a baseline that the store had changed in place). `change` now carries a copy of an object value, as it did for a list. A write to one side only (`value.end`) is written back as a whole range by the field so `change` and `dirty` follow.

## Records: `recordGrid` (slot pool across and down)
- `recordGrid` (E8.1, folder `components/composites/record-grid/`): the slot pool of `recordList` across and down, for card galleries and dashboards. Data `records` (an array or a keyed map) and `order` (optional keys to show), `key` (default `id`), the slot `row` (a row template: `$row` is the record) and `overscan` (rows, 0 to 20, default 2). Tokens, group `recordgrid`: `itemmin` (`calc({size.control.md} * 6)`, the smallest item width), `itemheight` (`calc({size.control.md} * 4)`, the item height) and `gap` (`{space.gap.md}`, between columns and below each item; the slot's bottom padding, so the measured height includes it). `messageList` sets it to `0px`. - Columns are `floor(width / itemmin)` and rows come from the height. A probe element sized by the two tokens and the scroller are watched by one `ResizeObserver` (`createGridViewport`), so a resize, a sidebar opening or a token write recomputes both without a layout read in the render path; the scroll offset is read once per animation frame. The controller writes `colCount`, `rowCount` and the window (`$.runtime.nodes.<path>.window`: `first` is the first item of the topmost visible row and `count` is the visible rows times the columns). The pool is `columns * (visible rows + 2 * overscan)` slots, at most 200, the cap taking from the overscan first.

The slot shows them as the custom properties `--sui-col` and `--sui-row`; its width is `100% / --sui-cols`, and it is placed with `inset-inline-start`, so the grid follows `dir="rtl"`. A resize that changes the column count re-points slots and rewrites those properties; the slot elements that remain are the same elements (the pool adds or removes slots at the end only). The first visible item stays at the top across a change of the column count.
- Not part of the first library; the catalog gate does not wait for it.

### `recordGrid`: measured row heights (E8.24)
- Items differ in height. Each slot element is observed with a `ResizeObserver` (`createSlotMeasure`); the border-box height from the entry goes into a height map keyed by record key (`createRowLayout`), so a height follows its record when the array reorders, a record that is not measured counts as the estimate (the `itemheight` token) and a record that is gone loses its entry once more heights are kept than there are positions. A slot is observed again when it shows another record (an element that is observed again is reported at once), so a record that happens to be as tall as the one before is measured too. `itemheight` is also the least height of a slot (`min-block-size`), which keeps the estimate a lower bound.
- A row is as tall as its tallest item. The offsets are the sums of the rows above, found with a binary search over the row tops; each slot shows its own as `--sui-offset` (the slot pool's new `offset` option writes `slotOffset`, and `syncOffsets` writes it again for a change of the heights). The height of the scroll content, `--sui-total`, is the sum of every row (the runtime property `contentHeight`), so the scrollbar changes by a measured height minus an estimate at a time. `rowCount` is the number of rows.
- When a measured height changes above the first visible row, the controller writes `scrollTop` by the difference (the offset of the first visible row after the change minus before it), after the new content height is written, so the visible records do not move; a change of an item in the window does not move `scrollTop`. The scroller has `overflow-anchor: none`, so the browser's own anchoring does not add to it. The scroll position, the sizes and the measured heights are all read from observer entries and one `scrollTop` read per frame; rendering stays write-only.
- Finding: the pool's slots are absolutely placed, so they are not in the flow and the browser cannot scroll-anchor them; the correction has to be made by the controller.

### `recordGrid`: grid keyboard and catalog entry (E8.25)
- The host is `role="grid"` with `aria-rowcount` (the rows) and `aria-colcount` (the columns), set by the controller as the layout changes. Each slot is `role="gridcell"` with `aria-rowindex` and `aria-colindex` (from 1), bound from its position in the view. The cells sit directly in the grid, with no `row` element between, as the component spec has it (an ARIA checker that wants `row` parents will say so); the grid has no accessible name of its own yet, so a page names it with an `aria-label` on the element.
- One slot is the tab stop: the cell of the record that last had focus, otherwise the first one shown (the pool's `slotTab`, so it follows the record, not the slot). The arrow keys move by position: Right and Left one item (swapped in right-to-left text, tested with `:dir(rtl)` so no style is read) and stop at the ends of the row; Down one row, and from the row above a short last row to the last item; Up one row. Home and End go to the first and last item of the row, Ctrl+Home and Ctrl+End to the first and last item. Page keys and wrapping are not used. A key typed in a field, textarea, select or editable element inside a cell stays with it.
- The target is scrolled into the window first (`bandOffset` over the layout, the least scroll that shows its row) and its slot is focused after the pool has refreshed, as in `recordList`. Rows that were never measured use the estimate, so the controller scrolls to the target again after each measurement that changed a height, until a report changes none. The focused slot is pinned while its record is out of the window, so scrolling away does not lose focus, and the pin follows the record across a change of the column count. A deleted focused record moves focus to the record that took its place.
- Catalog: the entry is built from the shape (tag `ui-record-grid`, size `composite`, slot `row` with `row: true`, tokens `recordgrid.itemmin`, `recordgrid.itemheight` and `recordgrid.gap`, the German overlay `record-grid.locale.de.json`, which is empty because the component has no content). Its example node is `{ "component": "recordGrid" }` (no property is required), which validates and mounts in English and German; `test/catalog.test.ts` also validates a document with `records` and a `row` template. The catalog test lists `recordGrid` with the later composites.

### `recordGrid`: scrolling by command and following the end (E8.19)
- `recordGrid` declares the commands `scrollTo` (value: a record key; puts the row of the record at the top, and throws for a key no record has, as `recordList` does) and `scrollToEnd`. The end is worked out from the layout, whose heights are estimates until the rows are measured, so after `scrollToEnd` the grid keeps the end in view while the heights settle and the content grows, until the user scrolls away; when the content is not yet as tall as the layout (the view follows the store a moment later) it tries again in the next frames, at most four.
- `follow` (default false) makes the grid do this from the start: it stays at the end while records are added, a measured height changes or the viewport is resized, unless the user has scrolled up. The runtime property `atEnd` says whether the view is at the end. It changes only when the scroll position changes, and a scroll the grid makes itself (the correction for a measured height above the window, a column-count change, the scroll to the end) is not read as the user leaving, so content that grows while the user is away neither moves the view nor changes `atEnd`.

## Composites: `messageList` (E8.19)
- `messageList` (folder `components/composites/message-list/`) is a conversation: a `recordGrid` of one column with measured heights, drawn as a runtime `body` node like the body of a `list`. Its `records`, `row` and `key` are store aliases of the message list's own, so the slot pool, the `$row` links and the recycling are the grid's; the grid gets `follow: true` and `--ui-recordgrid-itemmin` wider than any list, so it has one column. Data `records` (an array or a keyed map), `key` (default `id`).
- Slot `row`. The default row is stacked: a `panel` (column layout) holding an `avatar` (`_name` from `$row.author`) and a `content` `panel` (column layout) that holds a `markdown` body (`_text` from `$row.text`) and a `text` in the `caption` role (`_text` from `$row.time`). It is built on `panel` because a `toolbar` has no `layout` and lays everything out on one line. A record is therefore `{ id, author, text, time }`; `time` is the text shown. A row template the application gives replaces the whole default.
- Pinning. The view stays at the newest message while records are added or the last one grows (a streamed reply), unless the user has scrolled up; the grid does the work (`follow`), and the runtime property `pinned` is its `atEnd`. While the user is away and a message arrives, or the last message changes, the runtime property `unread` turns on and the view shows a button with the content `_newMessages` ("New messages", `de`: "Neue Nachrichten"). Pressing it, or the command `scrollToEnd`, takes the view to the end and the grid follows again; `unread` clears whenever the view is at the end. An edit of an older message does not show the button.
- Streamed replies are one record whose `text` is rewritten per chunk; the decision is recorded in the design (`stateui-ui-builder.md`, Preview and live state, "Streamed replies") and below.

### Decision: streamed replies (E8.19)
- One message is one record. The reply is added as `{ id, author, text: "", time, streaming: true }` at the next array index, each chunk is a write of the whole text so far to `<records>.<n>.text` (not a delta), and the last write sets the full text and `streaming: false`. These are ordinary path writes through the runtime's `write` message, at most one message per animation frame; they are live state, not tool writes, so they do not bump the document revision. The finished message is persisted by the snapshot or by `ui_state_set`. `messageList` handles a new record and a longer last record in the same way. Tests append records and rewrite the last record's `text` 12 times and check that the view stays at the end.

## Composed: `chatView` (E8.20)
- `chatView` (folder `components/composed/chat-view/`) is a `panel` (column layout) with a `messageList` (`children.messages`, which takes the remaining height) and a composer `toolbar` (`children.composer`) holding a `textareaField` (`children.input`: `autoGrow`, one row, `sendOnEnter`, label hidden) and a Send `button` (`children.send`). Exposed: `children.messages.records` (link it to an array of `{ id, author, text, time }`), `children.composer.children.input._placeholder`, `children.composer.children.input.on.send` (the send event name is the target of its `emit`) and the button text. German overlay: `chat-view.locale.de.json`.
- Send and Enter run `emit chat.send` with the typed text (trimmed) as the payload and then clear the field; Shift+Enter adds a line; an empty or blank composer sends nothing. The `emit` command sends the payload of the event that triggered it, and a button press carries no text, so the composer's `textareaField` raises the text itself: it gained the event `send`, the command `send` and the articulation `sendOnEnter` (default false), with no change to `stateui-app`. The button runs the `send` command on the field and the field's own `on.send` does the `emit` and the `clear`, so the button and Enter share one path. `chat.send` reaches the minion as turn input (E7.8, E7.9).
- `textareaField` `send`: the `send` command (and Enter with `sendOnEnter`) raises `send` with the trimmed text, unless the field is disabled, read-only or locked or the text is empty; Enter with a modifier other than Shift, and Enter while an input method composes text, are left alone. The field never clears itself.

## Fields: `fileField` (E8.22)
- `fileField` (folder `components/molecules/file-field/`) is a field family member on `createField` (the field contract: `change`, `invalid`, `valid`, `validate`, `reset`, `focus`, `clear`, `ui-field-connect`, `error`, `touched`, `dirty`, `required`, `disabled`, `readonly`, `titlePosition`, `width`). Decided by ADR-0017. Own properties: `accept`, `maxSize`, `maxFiles`; content `_label`, `_help`, `_choose`, `_drop`, `_remove` (`Remove {name}`) and `_errors`; runtime `rows`, `count`, `types`, `dragging`.
- Data `value` is a list of references `{ id, name, size, type }`, never bytes; a `<-value` link writes `$.data` with the list. `accept` is a list of media types: it is narrowed to the allowed list (PNG, JPEG, GIF, WebP, PDF, `.docx`, `.xlsx`, plain text, CSV, Markdown, JSON; the same list as `previewFiles.ts` in the host) and an entry outside it is ignored and reported once per distinct entry as a warning through `report.warning` (`code: "SUI-STATE"`, `path`: the node), the way `board` reports unmatched columns; an empty `accept` means the whole list. `maxSize` defaults to and is at most 10 MiB (`10485760`; a larger value is `SUI-STATE-INVALID`). `maxFiles` defaults to 1; the picker is `multiple` above 1.
- Files come from the picker (the button, `id="control"`) or are dropped on the field (`data-dragging` while a file is dragged over). Before a transfer the type (the browser's, else the one the extension stands for, which is also what is sent when the browser gave none), the size and the count (stored files plus transfers under way) are checked; a failure sets `error` to `accept`, `maxSize` or `maxFiles` and nothing is sent. Of several files in one pick, those that fit are sent and the first failure is the error. A new file is not accepted over `maxFiles`; remove one first.
- Transfer: the controller cannot reach the `mountApp` hooks, so it raises the bubbling, composed event `ui-file-transfer` (`FILE_TRANSFER_EVENT` of `@punyts/stateui-app`) with `{ file, onProgress, signal, respond }`; the dispatcher stops it and calls `respond` with the promise of `hooks.transferFile(file, { onProgress, signal })`. With no hook nothing answers and the error is `offline`. The reference the promise resolves with is appended to `value`; a rejection sets `error` to its `code` (`too_large`, `unsupported_type`, `quota`, `not_found`, `unauthorized`, `offline`, `cancelled`, `internal`; any other failure is `internal`). The error stays until the next pick, a removal or a successful transfer.
- Rows (`rows`): one per stored file (name and size in the locale's number form) and per transfer under way (name, percent and a `progress` bar). The remove button (named by `_remove`) removes a stored file from `value`, or, for a transfer, aborts it through `signal`; a late result for a removed transfer is ignored. The `clear` command and every reset (the `reset` command, and a form resetting the field, through the new `onReset` option of `createField`) abort the transfers under way too, so a late result cannot append a file. Nothing but the reference is written to the store, so a snapshot never holds file bytes.
- Rules and messages: `required`, `accept`, `maxSize` and `maxFiles` (also checked against a list written from outside) and the eight transfer codes each have an `en` message and a `de` overlay.

## Fields: `paintField` (G2.7, G2.8, G2.9)
- `paintField` (folder `components/molecules/paint-field/`) is a field family member on `createField` where a person paints on a canvas of `width` by `height` pixels (1..4096) with `brush` and `eraser` (`tools`), a colour of `colors` and a size of `sizes`; the current `tool`, `color` and `brushSize` are writable. Toolbar buttons and the commands `undo`, `redo` and `clear` work the stroke log of `src/shared/paint/`. `dirty` (runtime) is true while the painting has changed since it was last saved (with an empty value: while it is not blank). The value is a file reference `{ id, name, size, type }` or `{}`; the full documentation comes with G2.11.
- Saving (G2.8): when painting pauses for 1.5 s or focus leaves the field and it is `dirty`, the canvas is encoded with `toBlob('image/png')` (over `background` when set, else transparent) and handed to the host as a `File` named `<_label>.png` (`painting.png` without a label) through `ui-file-transfer` (`hooks.transferFile`). The next stroke aborts a pending save. On success `value` becomes the returned reference, `dirty` goes false, `changed` is raised, and the file it replaced is given back through `ui-file-release` (`hooks.releaseFile`, G2.5). A PNG over 10 MiB is `too_large` before it is sent; a failed upload keeps the strokes and `dirty` and sets the error to `too_large`, `unsupported_type`, `quota`, `offline` (also a host with no hook) or `internal`, with no new attempt until the painting changes. `clear` gives back the file it held; a reset aborts the save, restores the baseline value and gives back the files the field saved that it no longer holds; dispose aborts the save. Only files the field saved itself are given back; a file the value held at mount is left to the host's sweep, since a reset can restore it.
- Accessibility: a `role="group"` labelled by `_label` and described by `_description` (which says painting needs a pointer) and the error; the canvas is a `role="img"` and takes no keyboard input; the buttons use `aria-pressed` and are reached by Tab in the order tool, colour, size, undo, redo, clear, then the canvas. A form that needs an alternative pairs it with a text field.
- In a `form` (G2.9): a submit never sends a painting that is not saved. The field's `settle()` (see `form`) saves a `dirty` painting at once instead of after the pause and the form waits for that save (or for one already running, or a stroke under way), then validates: a finished save submits the new reference, a failed one leaves its code as the field's error and refuses the submit (`invalid`), and `required` with no file gives the `required` message. The collected value is `{ id, name, size, type }` or `{}`, the shape of one file of `fileField`. A form reset aborts the save, empties the canvas, restores the baseline value (`{}` for a new field), clears `dirty` and gives back the files the field saved. Tests: `test/composites/form-paint-field.browser.test.ts`.

## Graphics: `drawing` and the 2D shapes (G1.3)
- **Overview.** A `drawing` node (category `graphics`) holds shape nodes in its `children`; shapes are accepted nowhere else (`drawGroup` and `drawRepeat` hold shapes in turn). The drawing reads the shape nodes into a shape tree (`src/shared/drawing/`, see `src/shared/README.md`) and hands it to a renderer: SVG by default, or a canvas. A shape value is a literal, a theme token (`"fill": "{color.accent.base}"`, recoloured on a theme or mode switch) or a link (`"<-cx": "$.data.chart.x"`); in a `drawRepeat` row, `$row` links read the record, as in a list row. A shape with `interactive: true` and a `_label` is pressable and focusable, and its `on` entries run on `press` and `hover` like a button's. The checks (`SUI-STATE-PAINT`, `SUI-STATE-TOKEN`, `SUI-STATE-LABEL`) and the run-time reports (`SUI-RUN-DRAW`, `SUI-RUN-CAP`) are in the stateui-app README; how an agent checks a drawing (`ui_screenshot`, `ui_tree` with `rendered: true`, `ui_interact` on a shape path) is in the stateui-mcp README. A seat map, where pressing a seat records it:

  ```json
  {
      "component": "drawing",
      "viewBox": { "x": 0, "y": 0, "width": 200, "height": 120 },
      "_title": "Seat map",
      "children": {
          "stage": { "component": "rect", "x": 40, "y": 0, "width": 120, "height": 20, "radius": 4, "fill": "{color.border.base}" },
          "caption": { "component": "drawText", "_text": "Stage", "x": 100, "y": 10, "anchor": "middle", "baseline": "middle" },
          "seats": {
              "component": "drawRepeat",
              "<-records": "$.data.seats",
              "row": {
                  "component": "circle", "<-cx": "$row.x", "<-cy": "$row.y", "r": 6, "<-fill": "$row.fill",
                  "interactive": true, "<-_label": "$row.name",
                  "on": { "press": { "command": "set", "target": "$.data.ui.seat", "value": "$row.id" } }
              }
          }
      }
  }
  ```
- `drawing` (folder `components/composites/drawing/`, category `graphics`) holds a 2D scene: `renderer` (`svg`, the default, or `canvas`), `viewBox` (`x`, `y`, `width`, `height`), `fit`, `paints` (named gradients: `kind`, `stops` of `offset` and `color`, `angle`, `center`), a `children` slot that takes only the shapes, `_title` (default "Drawing", German "Zeichnung") and `_description`. Tokens: `drawing.background` and `drawing.height`. The view is a `role="img"` box named by the title, described by the description when there is one, with a `.surface` carrying `data-renderer`, which the renderer draws into. **SVG renderer (G1.5):** with `renderer: "svg"` the controller reads the shape nodes (links followed) and draws them as SVG (`src/shared/drawing/svgRenderer.ts`), again on any change at or below `children`, `paints`, `viewBox` or `fit`, writing only what differs; each shape element carries `data-shape-path` and `data-shape-kind`. Token colours are `var(--ui-…)` presentation attributes, so a mode switch recolours them and a stylesheet rule can override them; a shape with no `fill` takes the text colour. Without a `viewBox` the drawing fits its content. A node that is not a 2D shape or a shape with a value it cannot draw is left out and reported once (`SUI-RUN-DRAW`), a colour that resolves to nothing once as `SUI-STATE-PAINT` or `SUI-STATE-TOKEN`; the other shapes draw. The `ui-drawing` element carries `data-render="pending"` from a redraw request (first draw, state change, resize, theme or mode switch) until the change is on screen, then `"ready"`. `drawImage` comes with G1.9b. **`drawRepeat` in SVG (G1.5b):** a repeat draws one `g` with one element per record (its `row` template bound to the record by the row binder, no node per record), each carrying `data-shape-path` `<repeat>.rows.<recordKey>` and the template's `data-shape-kind`; at most 2,000 copies in SVG, the first ones, the cut reported once as `SUI-RUN-CAP`. The controller watches the record paths and the store paths the template reads, so adding, changing or removing one record adds, changes or removes only its element. An empty or missing record set draws nothing and reports nothing. Tests: `test/composites/drawing.browser.test.ts`, `test/composites/drawing-repeat.browser.test.ts`, `src/shared/drawing/svgRenderer.browser.test.ts`. **Canvas renderer (G1.6):** with `renderer: "canvas"` the same shapes are drawn into a `canvas` (`src/shared/drawing/canvasRenderer.ts`) at the screen's pixel ratio (at most 2), sized from its own `ResizeObserver` entry and drawn again on a resize. Token colours and fonts are read from the computed style on each draw, so a theme or mode switch (`$.theme.active`) recolours the bitmap; a `font` the theme lacks falls back to the page font. All canvas drawings draw in one animation frame, once per frame however many changes come, and only the ones that changed. A `drawRepeat` draws up to 20,000 copies (the cut reported once as `SUI-RUN-CAP`) with no element per record. Hit testing uses the shapes' geometry, as in SVG. The bitmap has no element per shape; the proxy buttons of G1.7c (below) carry `data-shape-path` for the interactive shapes. Tests: `test/composites/drawing-canvas.browser.test.ts`. **Events in SVG (G1.7):** a shape with `interactive: true` is a button (`role="button"`, `tabindex="0"`, `aria-label` from `_label`) and the only thing in the svg that takes pointer events; a non-interactive shape is not hit (`pointer-events: none`) and not in the tab order. A click, or Enter or Space on the focused shape, raises `press` on the `ui-drawing` element, and the pointer entering the shape raises `hover` (once per entry, again after it left), as bubbling, composed events with `detail: { shape, key, x, y }` (the shape's state path, its key or a copy's record key, the position in drawing units). The dispatcher runs the shape's own `on` entry, or for a `drawRepeat` copy its row template's with `$row` at the record, so `"on": { "press": { "command": "set", "target": "$.data.ui.seat", "value": "$row.id" } }` in a seat template records the pressed seat. While a shape is interactive the drawing is `role="group"` (an `img` hides its children from assistive technology). Tests: `test/composites/drawing-events.browser.test.ts`. **Events in canvas (G1.7c):** each interactive shape (not hidden) of a canvas drawing gets a proxy `button` in the shadow root (in a `.proxies` layer before the canvas), in drawing order, with `data-shape-path`, `data-shape-kind` and `aria-label` from `_label`, kept in step with the tree (added, removed and moved with the shapes). A proxy lies over the shape's bounds in CSS pixels (cut to the canvas) with `opacity: 0` and `pointer-events: none`: it has a real box for `ui_interact`, is in the tab order and is read by a screen reader, but a pointer never lands on it. Enter or Space on a focused proxy, or an element-level click on it (`element.click()`), raises `press` at the shape's centre (a held key does not repeat it). A pointer click on the canvas raises `press` for the topmost interactive shape at that point (`hit()`), and the pointer entering one raises `hover` once per entry, with the same `detail` as in SVG. Shapes that are not interactive are passed through, as SVG's `pointer-events: none` passes them, so a label drawn over a seat does not block it; a click on empty space or on a non-interactive shape raises nothing. A proxy has no visible focus ring yet. Tests: the canvas variants in `test/composites/drawing-events.browser.test.ts`.
- Shapes are shape-tier components (a `state.json` and no element), accepted only in a slot that names them: atoms `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `path`, `drawText` (`_text`, `anchor`, `baseline`, `font`, `fontSize`), `drawImage`; molecules `drawGroup` (`children` and a `clip` shape) and `drawRepeat` (`records` and a `row` template). All merge the partials of `src/shared/shape/` (paint, transform, interaction, motion); their events are `press`, `hover` and `dragEnd`. Shapes have no tokens of their own. The shared properties: paint `fill`, `stroke` (a colour, a `{token}` or a name of the drawing's `paints`), `strokeWidth`, `opacity`, `dash`, `cap`, `join`; transform `x`, `y`, `rotate` (degrees), `scale` (a number or `[sx, sy]`), `origin`; interaction `interactive`, `_label`, `draggable`, `bounds`, `step`; motion `transition`, `animate`. `draggable`, `bounds`, `step`, `transition` and `animate` are accepted and checked, but the renderers do not act on them yet, and nothing raises `dragEnd` yet.
- Checks (stateui-app): a paint name the drawing's `paints` does not define is `SUI-STATE-PAINT`, an unknown `{token}` `SUI-STATE-TOKEN`, and an `interactive` shape without `_label` warns `SUI-STATE-LABEL`. `test/graphics.test.ts` covers them.

## Testing components
`mountComponent(name, nodeState, options?)` (`test/harness/mountComponent.ts`) mounts one component through `mountApp` in a browser test. `options` are `mode`, `brand`, `motion` (overlay names), `locale`, `data` (the document's `data`) and `locales` (the document's own overlays per language).
